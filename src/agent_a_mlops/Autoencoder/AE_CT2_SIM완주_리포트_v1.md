# CT²(AE) S1 수동 완주 — SIM 실데이터 리포트 v1

> 작성: 에이치(A) · 2026-07-30 · 데이터: `synthetic_1y`(팀 공용 시뮬 — 1년 합성)
> 목적: 챔버 분리 미완(WP-E)을 **단일 챔버 재구성으로 일시 우회**하고, CT² 파이프라인
> (조립→학습→게이트→감시)을 **실데이터로 관통**한다 (플래너 v2 S1 "수동 완주 + shadow 대조").
> ⚠️ SIM 데이터·우회 기반 결과 — 실운영 값 아님. 스위치(`ct2_auto_generate`·`ct2_auto_promote`) 전부 false 유지.

## 0. 한 줄 결론

파이프라인이 실데이터로 **끝까지 돈다.** 그리고 자동 검증 게이트는 **고무도장이 아니다** — 세 번 다
`FAIL(exit 2)`로 배포를 **차단**했다. 차단 사유가 정확했고, 그 과정에서 **WP-D(표본 수·임계 재산정)와
WP-F(firm 한계 sensor_window 정합)가 가설이 아니라 실측으로 확인**됐다. 홀드아웃 메커니즘(D14)이
없었다면 세 번 다 조용히 배포됐을 번들이다.

## 1. 재구성 (WP-E 일시 우회)

- **원본**: `synthetic_1y/synth_2019-05·06.csv.gz` — C1~C65 전체 스키마(merged), `C24=C24_0` 단일 챔버, C6_0=정상/C6_1=이상.
- **레짐 선택**: major PM(요란) 경계 = 2019-04-22·2019-08-20. 05·06월은 **PM-1 하류 정상 베이스라인 레짐**(요란 PM 후 재학습 시나리오와 정합).
- **단일 챔버 우회**: 전 행 `C24 → SIM_CH_1` 재라벨. 챔버가 하나이므로 공용 모델 1개 문제(WP-E)가 이 실험에서는 비활성.
- **정상 윈도우 3종**(시간순 앞 N wafer, C6_0): **1500 / 3000 / 6000** — N 스윕용.
- **이상 세트**: C6_1 79 wafer(같은 챔버 라벨) — 감시 프로브·AE 검출력용.

## 3. 핵심 발견

### 3-1. 게이트가 실제 게이트다 — 홀드아웃이 항진명제를 깼다

retrain이 보고한 **적합-VAL L5는 세 번 다 ~1.7~2.1%**(임계 2% 부근, "통과처럼 보임"). 그러나
게이트가 **calib 미적합 홀드아웃**에서 재보니 L5 = **4.7~22.2%**. calib 앵커(P50·P90·P98.5)를
적합한 그 표본으로 L5를 재는 옛 방식이면 세 번 다 조용히 배포됐고, 운영에서 정상 wafer를
5~22% 오경보했을 것이다. **홀드아웃 메커니즘(D14)이 그 자기실현을 차단했다** — 설계 의도대로.

### 3-2. ★근본 레버 = calib 적합 표본 크기 (WP-D 실측 첫 3점)

홀드아웃 L5가 **적합 표본 N에 단조**: 145장→0.222, 287장→0.073, 558장→0.047. 동시에 P95(1.00→0.19,
6000에서 통과)·프로브(0.83→0.71→0.89)·앵커 간격(1500서 뭉침→3000+서 해소)도 N과 함께 개선. **recon
RMSE는 전 구간 양호**하므로 이는 **저학습이 아니라 calib 일반화의 표본 의존성**이다.

**함의 (WP-D 직결)**: ⓐ 현 게이트 임계(`l5_max 0.02`·`calib_mean 0.05±0.02`·`probe_min_detect 0.90`)는
원 학습(REPORT_05) 역산 출발값이라 **SIM 학습 번들엔 상시 FAIL** — 임계 재산정이 필수(가설 아님, 실측).
ⓑ 게이트를 통과하려면 적합 표본을 **6000장보다 크게**(홀드아웃 L5를 0.02로 끌어내리려면 외삽상 1만+
정상 wafer) 잡거나 임계를 SIM 정합값으로 내려야 한다. ⓒ `ct2_min_train_wafers=1000`은 **조립 게이트
하한일 뿐 검증 게이트 통과선이 아니다** — 둘을 혼동하면 안 된다. 이 3점이 WP-D 스윕(n×시드)의 착수 데이터.

### 3-3. firm 한계 sensor_window 정합 (WP-F 실측)

firm 한계를 **정착(C42=0)만**으로 뽑아 소급 필터에 넣으니 정상 wafer를 **3000/3000 전량 제외**했다 —
`retro_filter`가 step4의 **과도(C42=1) 행까지** 검사하는데 과도 스파이크가 정착 mean±3σ를 벗어나기
때문. step4 **전체 분포 분위수(±3σ 등가)**로 재산출하니 2869/3000 정상 통과. → **WP-F의 "sensor_window
='settled' 한정이 맞는가" B 확인 항목이 실측으로 확인**됐다: 소급 필터의 한계 정의 창과 검사 창이
일치해야 한다(정착 한계면 정착 행만 검사, 아니면 step4 전체 한계).

## 4. WP-C 배포 후 감시 — 실데이터 확인

**AE 검출력** (win6000 번들로 스코어): 정상(C6_0, n=2869) ae_score mean 0.054·P95 0.146·>qual 2.6% /
이상(C6_1, n=79) mean **1.000**·>qual **100%**. AE가 실이상을 정상 대비 **18.4배** 높게, **전량 검출**.

**감시 판정** (`ct2_deploy_monitor.evaluate`, 실스코어):
- **정상 AE**: SPC 발화(C6_1) 20건 중 AE 침묵 **0건** → `rollback=False` (오발화 없음 = "미탐 0건"의 실데이터 확인).
- **실명 AE**(같은 SPC 발화에 AE 침묵으로 치환): 교차침묵 1.0 → `rollback=True`.

→ 감시가 **정상 AE엔 조용, 실명 AE엔 발화**. WP-C 로직이 실트레이스에서 의도대로 동작.
(⚠️ 실증의 나머지 = 롤백 1회 실측·`_fetch_window` 스키마 결합은 라이브 DB 필요 — S3 잔여.)

## 5. Shadow 판정 (엔지니어 소견 — 플래너 S1 요구)

게이트: **FAIL 3/3**. 엔지니어(A) 소견: **게이트 판정에 동의.** 사유:
1. 번들의 정상-조용성이 홀드아웃에서 실제로 부족(L5 4.7~22%) — 운영 오경보로 직결될 값. 차단이 맞다.
2. 실이상(C6_1) 검출은 완벽(100%)하므로 **모델이 무능한 게 아니라**, calib 일반화·프로브 민감도가
   현 임계에 못 미친 것. → **임계 재산정(WP-D)** 없이는 SIM 번들이 통과할 수 없음이 확인됨.
3. 따라서 이 shadow 대조의 결론은 "게이트를 느슨하게" 가 아니라 **"WP-D 스윕으로 임계·N을 SIM 정합값으로
   확정"** + firm 한계 창 정합(WP-F). 게이트를 통과시키려 calib을 적합 표본 전체로 되돌리는 우회는
   **금지**(홀드아웃 설계 D14의 자기실현으로 회귀).

## 6. 정직한 한계

① **SIM·단일 챔버 우회** 결과 — 실운영·멀티 챔버 아님. 챔버 분리(WP-E)는 여전히 선결.
② firm 한계는 **데이터 유도 스탠드인**(정상 윈도우 분위수) — 실제는 B `control_limits`. WP-F B 확인 2건 유효.
③ 주입 이상 대신 **C6_1(이상 레짐)을 anomaly로 사용** — events_ledger의 센서층 주입(C11/C31/C58/C62)은
   전역 wafer 인덱스 매핑이 필요해 이번엔 C6_1로 대체. 센서층 주입 검출은 후속.
④ retrain epoch·윈도우는 데모용(400ep 고정·앞 N wafer) — WP-D 정식 스윕은 시드 반복·시간축 랜덤 분할 포함.
⑤ 게이트 3점은 **스윕의 착수 데이터**이지 확정 임계가 아니다.

## 7. 재현 절차 (torch 2.13·sklearn 1.7 · 인터랙티브 콘솔 — TSR-0001)

```bash
# 1) 재구성(단일 챔버 정상 윈도우) — synthetic_1y에서 C6_0 앞 N wafer, C24→SIM_CH_1
# 2) firm 한계(step4 전체 분위수 0.00135/0.99865) → firm_limits_SIM_CH_1.json
# 3) 조립
python scripts/ct2_assemble_trainset.py --from-csv <window.csv> --chamber SIM_CH_1 \
    --limits-json firm_limits_SIM_CH_1.json --min-wafers 1000 --out <ts_dir>
# 4) 학습 (cwd = src/agent_a_mlops/Autoencoder)
python -m ae_pipeline.retrain --data <ts_dir/ct2_trainset_*.csv> --out <bundle> --input-schema auto
# 5) 게이트
python -m ae_pipeline.validate_bundle --bundle <bundle> --data <ts_dir/ct2_trainset_*.csv>
#    exit 0=PASS / 2=FAIL / 1=오류. 리포트=<bundle>/validation.json
```
산출물(스크래치): `outputs/sim_ct2/` — 윈도우 CSV·firm 한계·트레인셋·번들 3종·validation.json·감시 스코어.
