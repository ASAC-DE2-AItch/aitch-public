# 구조 객체화 개정안 — 라이브 루프 사전점검 (v1)

> **작성**: 2026-07-27 · A(에이치) · 리뷰 전용 — **코드 수정 없음, 수정안 제시만**
> **전제 루프**: consumer 라이브 루프에서 `collector(조인) → context_score(4축+combine) → publisher(억제·발행)` 체인이 wafer마다 돌아 `fdc.alert`까지 발행.
> **리뷰 기준**: ① 버그 ② 예외 처리 누락 ③ 성능.
> **범위**: 현재 **구현된** 코드만 (prediction_cache · collector · score_spc/tttm/pred · config · spc_consumer 배선부). 미구현(score_ae·오케스트레이터·combine·publisher)은 §5 구현 노트로만.
> 우선순위: **P1 = 라이브 전 필수 / P2 = 권고 / P3 = 선택.**

## 0. 대상 파이프라인 (구조)

## 1. P1 — 라이브 전 필수 수정

### 1-1. collector seam 호출 예외 미격리 → 한 wafer 스코어링 실패가 TTTM 이력·커밋까지 죽임

- **파일**: `src/agent_b_spc/spc_consumer.py` `_process_wafer` (L448~450) — **B 소유, B 협의 필요**
- **현상**: 
  ```python
  if self.collector is not None:           # ① 실시간 alert 먼저
      self.collector((wafer_id, ...))      #    ← try/except 없음
  self._persist_tttm(tttm_obj)             # ② 이력 적재 마지막
  ```
  collector가 라이브로 붙으면 이 한 줄이 **collector→score→publisher 전체 체인**이 된다. 체인 어디서든 예외가 나면 ⓐ `_persist_tttm`(TTTM 이력 적재)이 건너뛰어지고 ⓑ `_flush`의 except로 빠져 **offset 커밋도 안 됨** → 재시작 시 대량 리플레이. 같은 함수 안의 nelson/tttm `feed`는 개별 격리돼 있는데(엔진 격리 패턴) collector 호출만 예외 노출.
- **수정안 (권고)**: collector 호출을 nelson/tttm과 동일 패턴으로 개별 try/except:
  ```python
  if self.collector is not None:
      try:
          self.collector((wafer_id, chamber_id, ts, violations, tttm_obj))
      except Exception:
          logger.exception("collector/score 체인 실패 — SPC 적재는 계속: %s", wafer_id)
  self._persist_tttm(tttm_obj)
  ```
- **트레이드오프 명시**: 격리하면 해당 wafer의 **alert은 유실**(best-effort)되지만 SPC 기록·커밋은 보전. 현행(미격리)은 반대 — 알람 재시도 가능하지만 결정적 버그면 커밋이 영영 뒤처짐. **"SPC 기록 = must, alert = best-effort + 실패 카운터"**를 권고. 실패 wafer_id 카운터/메트릭 추가로 유실 추적.

### 1-2. 축 함수가 total function이 아님 — 비정상 입력에 예외 전파

- **파일 ①**: `src/common/context_score/axes/score_pred.py` (L92 부근, **A 소유 — 내 코드**)
  - `float(predicted)` / `float(p95_threshold)` — 값이 문자열("N/A")·비수치면 `ValueError/TypeError` 전파 → 1-1 경로로 wafer 전체 사망.
  - **수정안**: 수치 검증 가드 후 0.0 + warning:
    ```python
    if not isinstance(predicted, (int, float)) or isinstance(predicted, bool):
        logger.warning("score_pred: predicted_c65 비수치(%r) → 0.0", predicted)
        return 0.0
    ```
    (p95_threshold 동일. bool 제외는 `float(True)=1.0` 오계산 방지.)
- **파일 ②**: `src/common/context_score/axes/score_spc.py` `_exceedance_sigma` (L38)
  - `v["control_limit_upper"]` 등 **직접 인덱싱** — 위반 dict에 키가 없으면 KeyError 전파. nelson 엔진 산출엔 있지만, 계약을 코드가 강제하지 않음. **B 소유, B 협의**.
  - **수정안**: `.get()` + None 가드 → 해당 위반만 e3=0 처리(+warning). 또는 1-1 격리로 충분하다고 보고 유지(단, 한 개 위반의 키 결측이 wafer 전체 alert을 죽이는 반경은 그대로).
- **원칙 제안**: 축 함수 4종은 "**어떤 입력에도 raise하지 않고 float 반환**"을 계약으로 못박기(테스트로 강제). 1-1 격리는 최후 방어, 축 가드는 1차 방어.

### 1-3. prediction_cache.get() 얕은 복사 — 중첩 객체(shap 리스트) 캐시 오염 가능

- **파일**: `src/common/context_score/prediction_cache.py` `get()` (**A 소유 — 내 코드**)
- **현상**: `return {k: v for k, v in entry.items() if k != "_read"}` — **1단계만 사본**. `shap`(list of dict) 같은 중첩 객체는 참조 공유라, 하류(joined 소비자·리포트 조립 등)가 리스트를 변조하면 **캐시 원본이 오염**되고 이후 get()들이 오염값을 받음.
- **수정안 (택1)**:
  - ⓐ `copy.deepcopy(entry)` 후 `_read` 제거 — 가장 안전. wafer당 1회·shap 3개라 비용 무시 가능. **(권고)**
  - ⓑ upsert 시점에 `shap`을 tuple(불변)로 변환 저장 — 복사 비용 0, 단 하류가 list 기대 시 마찰.
  - ⓒ 계약 문서에 "반환 dict는 read-only" 명시 — 비용 0이지만 강제력 없음(리뷰로만 방어).

## 2. P2 — 권고 (정합·설계 리스크)

### 2-1. 예측 도착 vs 조인 타이밍 레이스 — 조인 시점 캐시 miss가 구조적으로 잦을 수 있음

- **파일**: 아키텍처 수준 (A `agent_a_mlops/consumer.py` 발행 시점 + B `_flush` 경계)
- **현상**: A의 예측 발행과 B의 wafer 완성(flush→조인)이 **같은 신호(다음 wafer 첫 row)**로 트리거된다. B의 조인은 poll 루프 안에서 즉시 실행되는데, A의 예측은 [A poll → 추론 → produce → broker → B poll] 왕복을 거친다 → **wafer N의 조인이 N의 예측 도착보다 먼저일 확률이 높음** → 예측 결측(★③ 경로)으로 AE/pred 축이 상시 0 + (Step 5 후) 미조인 만료 WARNING 반복 가능.
- **수정안 (택1 또는 조합, A·B 공동 결정)**:
  - ⓐ **미스율 실측 먼저**: collector에 예측 hit/miss 카운터 추가 → 리허설에서 실측 후 결정. **(1순위 권고 — ★③이 이미 "SPC 안 막음"을 확정했으므로 데이터로 판단)**
  - ⓑ 조인 짧은 유예: miss 시 해당 wafer 조인만 수 초 지연 재시도(SPC 알람은 즉시, 예측 늦으면 그때 0). 복잡도 증가 주의.
  - ⓒ A 발행 조기화: wafer 마지막 step 완료 시점(경계 전) 발행 검토 — A 파이프라인 변경 필요.
- **참고**: TTL(900s)은 이 레이스와 무관하게 충분(레이스는 초 단위).

### 2-2. config 통합 순서 — 신규 pred 3키 하드 요구

- **파일**: `src/common/context_score/config.py` `load()`
- **현상**: `context_score_pred_p95_scale`·`_w_cap`·`_gated_phases`를 `_key()`로 하드 요구 — params.yaml 병합이 안 된 브랜치에서 `ContextScoreConfig.load()` 자체가 실패(의도된 명시 실패이나, B의 Step 5 배선 브랜치가 구 params로 돌면 즉사).
- **수정안**: 코드 유지(헌법 6-1 정합). 대신 **B에 통보 + 브랜치 병합 순서 명시**(config 먼저) + `config_파라미터_합의안` doc-sync 티켓. 코드로 풀려면 `spc.get(...)` optional 읽기로 완화 가능하나 조용한 기본값 금지 원칙과 충돌 — 비권고.

### 2-3. `_extract_ts` — A 발행 timestamp(ISO 문자열)를 못 읽어 역전 방어가 실질 도착순

- **파일**: `src/common/context_score/prediction_cache.py` `_extract_ts` (**A 소유 — 내 코드**)
- **현상**: `isinstance(v, (int, float))`만 허용 — A producer는 `timestamp`를 **ISO-8601 문자열**로 발행(`build_message`) → 항상 수신시각 fallback. ts 역전 방어가 "소스 시각"이 아니라 "도착 순서" 기준으로 동작(단일 파티션·단일 producer라 실해는 낮지만 설계 의도와 어긋남).
- **수정안 (택1)**:
  - ⓐ ISO 문자열 파싱 추가: `datetime.fromisoformat(v.replace("Z","+00:00")).timestamp()` (try/except로 실패 시 fallback 유지). **(권고)**
  - ⓑ 계약 유지(도착순 방어) + 헤더 주석에 명시 — 현행 동작 문서화만.

### 2-4. 오케스트레이터 구현 노트 — 주입 키는 normalize 이후에

- **파일**: (신규 구현 대상) `context_score.py` — **§5와 세트**
- **근거**: `collector._normalize_prediction`의 `_PREDICTION_KEY_MAP`은 **화이트리스트**라, score_pred가 읽는 런타임 주입 키(`phase`·`p95_threshold`)는 normalize를 통과 못 함. 주입은 반드시 `build_joined()` **이후** `joined["prediction"]` dict에 해야 함(또는 맵에 passthrough 추가 — B 협의).

## 3. P3 — 선택 (성능·로그 위생)

### 3-1. `_enforce_capacity` — full 상태 upsert마다 O(n) min 스캔

- **파일**: `prediction_cache.py`. max_entries=5000 + 231 wafer/day에선 무해. **대량 replay/백필**(수만 msg 연속 upsert) 시에만 5000-스캔 × N. 
- **수정안**: 필요 시 heapq(ts, wafer_id) 또는 OrderedDict LRU로 교체. 현 규모에선 보류 권고.

### 3-2. score_spc 미등록 rule_id 경고 — wafer마다 반복 (로그 스팸)

- **파일**: `score_spc.py` `_stream_score` (L49~51). 알람 폭풍 시 동일 경고 다발.
- **수정안**: 모듈 레벨 `set`으로 최초 1회만 warning(이후 debug), 또는 로거 필터. 소규모라 보류 가능.

### 3-3. collector 예측 결측 INFO — 2-1 레이스와 결합 시 매 wafer 출력

- **파일**: `collector.py` L95. 레이스 미해결 상태로 라이브 가면 wafer마다 INFO.
- **수정안**: 2-1ⓐ(카운터)와 세트로 — 로그는 N건당 1회 요약 or debug 강등, 미스율은 카운터/메트릭으로.

### 3-4. `_ever_read` 재시작 리셋 — 동작 명시만

- **파일**: `prediction_cache.py`. 재시작 시 `_ever_read=False`로 초기화 → 첫 get 전 미조인 만료가 다시 DEBUG(브링업 억제). **의도된 동작**(재시작 브링업도 폭주 방지)이나, "재시작 직후 구간의 진짜 stranded는 WARNING이 안 찍힘"을 운영 문서에 명시 권고. 수정 불요.

## 4. 무결 확인 (리뷰했고 문제 없음)

- `score_tttm` — None/빈 dict/`score` None 가드(`or 0.0`), net 음수 허용(설계 의도), 순수성 OK.
