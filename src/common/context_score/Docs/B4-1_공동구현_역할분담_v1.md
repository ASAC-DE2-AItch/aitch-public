## 0. 전제 (확정 사항)

- **아키텍처**: SPC(Nelson·TTTM)+조인+score+발행이 **공용 모듈**(A+B 공동 소유). Kafka 컨슈머가 raw·prediction 둘 다 구독.
- **drift_score = wafer 단위** 발행 확정 → 예측 캐시·조인은 `wafer_id` 1:1.
- **Step 1(컨슈머+팬아웃+엔진)은 완성·머지** (#47·#48 → 현재 브랜치) — `spc_consumer.py`가 `fdc.raw → Point → Nelson·TTTM → collector((wafer_id, spc_flags, tttm_obj))` seam까지 (seam 시그니처 현행 확인). **우리 작업은 이 seam(=collector)부터.**
- **B6-3(가한계) 완료** (2026-07-24) — 억제가 소비할 **`get_phase`**(provisional Phase 0~2 상태머신)가 이미 있음. 컨슈머는 이미 **`fdc.raw`+`fdc.correction`(B5-1a)+`fdc.agent`(B6-3-c)** 다토픽 구독 중 → B4-1은 **`fdc.prediction`만 추가**.
- **환경 구성(공유 폴더·소유권·헌법 3-1 개정)은 이월** — 본 문서는 *구현 내용·역할*만.

## 2. 축별 서브함수 모듈화 (A/B 경계를 코드로)

Step 4 `context_score`를 축마다 순수 서브함수로 쪼갠다 → 각자 자기 함수만 채우고 `combine`만 공동.

```
context_score(joined, cfg):
    s1 = score_spc(violations)        # B — 룰 기본점·지속성·위반크기
    s2 = score_tttm(tttm)             # B — score 가점·reference_suspect 감점
    s3 = score_ae(drift, anomaly)     # A — drift 밴드·anomaly z
    s4 = score_pred(predicted_c65)    # A — P95 방향 가중항
    return combine([s1,s2,s3,s4], cfg)  # 공동 — naive→grouped 교체는 여기만
```

- 인터페이스 계약: 각 서브함수는 `float 기여값` 반환, 부작용 없음(순수).
- `combine`이 naive(선형합산)→grouped(2단집계)로 바뀌어도 **서브함수 시그니처는 불변**.

## 3. Step별 상세

### Step 2. `fdc.prediction` 구독 + 캐시 — **A**

작업:
- 컨슈머 구독 목록에 **`fdc.prediction` 추가** (현재 fdc.raw·fdc.correction·fdc.agent 구독 중)
- 역직렬화 + 필수 필드 검증(`wafer_id, drift_score, predicted_c65`), 실패 시 skip+로그(헌법 6-2)
- 캐시: `{wafer_id → {predicted_c65, drift_score, anomaly_score, shap_top3, is_qual, ts}}` 최신값
- **수명 관리**: 조인 후 제거 or TTL/상한(메모리), 고아 예측 처리

입출력: `fdc.prediction` 메시지 → wafer_id 키 캐시
검증: 예측 주입 → 조회 성공 · TTL 동작 · 결측 케이스

### Step 3. collector 뼈대 · 조인 — **B** (조인 정책은 공동)

작업:
- **collector 함수 구현** (seam이 호출하는 callback) — `[B]`
- **seam 시그니처 조정**: 지금 `spc_flags`(축약)만 넘김 → **full `violations[]`**(current_value·관리선) 실어나르게 (`nelson.feed(p)` 반환이 이미 full, 누적만 변경) — `[B]`
- 캐시에서 `wafer_id`로 예측 조회 → 조인 구조체 `{wafer_id, chamber, ts, violations[], tttm, prediction}` — `[B]`
- **예측 결측 정책** (대기 vs AE=0), raw/pred 도착 순서 무관 처리 — `[공동 결정]`
- **is_qual 라우팅** (Qual wafer 경로 분기) — `[B]`

입출력: `(wafer_id, violations, tttm_obj)` + 예측 캐시 → joined event
검증: 세 갈래 wafer_id 정합 · 예측 결측 시 정책대로

### Step 4. context_score(naive) + 계측 — **B(SPC축) / A(AE축) / 공동(combine·계측)**

작업:
- `score_spc(violations)` · `score_tttm(tttm)` — `[B]`
- `score_ae(drift, anomaly)` · `score_pred(predicted_c65)` — `[A]`
- `combine(axis_scores, cfg)` **naive 버전**(선형합산·설계 §4 가안 배점) — `[공동]`
- **규칙 준수**: pred 단독불가·가한계 Phase 0~1 가중 0 · 과도(C42) ×0.5 · `clip 0~100` — `[공동]`
- **계측 훅(P0)**: `e1~e8·m1` raw 기여를 메타(wafer·sensor·step·window)와 함께 `contribution_log` 덤프 — `[공동]`
- 가중치는 `params.yaml` 로드(`context_score_agent_min`·`context_score_pred_weight`)

입출력: joined event + cfg → `context_score(0~100)` + 기여 로그
검증: 설계 §5 예시 6종 점수 재현(예: N3+TTTM+AE+pred=72) · 게이트 31 동작

### Step 5. 억제 · 발행 · 적재 — **B**

작업:
- **억제 집행**(결정5, 발행 전 게이트): **`get_phase` 소비**(B6-3 provisional 상태머신) → Phase 0 억제 · baseline 없는 그룹 skip
- **alert_id 채번** (`ALERT-YYYYMMDD-CHAMBER-SEQ`)
- **`fdc.alert` 조립**(계약 §3): alert_id·chamber_id·violations[]·tttm·context_score·prediction_context·suspect_window
- **센서명 매핑**(`sensor_map.yaml`, 표시 계층만 — C코드 유지)
- Kafka producer 발행(`key=chamber_id`) + **`spc_violations` INSERT**(전 건, alert_id·context_score)
- graceful shutdown · 발행 실패 처리

입출력: scored event → `fdc.alert` 메시지 + `spc_violations` rows
검증: **E2E 관통**(주입→alert→DB) · 계약 §3 스키마 · alert_id 유일성

### Step 5b. B9 crazy wafer — 챔버별 Y read-side — **B**

> 로드맵(2026-07-24) B4-1 범위 명시. 조인된 예측을 소비하므로 Step 3 이후.

작업:
- 조인된 예측(`predicted_c65`·`anomaly_score`)으로 **crazy wafer 판정** (params `crazy_wafer` OR 조건: P99 초과 **또는** anomaly ≥ 3.0×)
- **글로벌 상수(1572) 대신 챔버별 `y_thresholds.p99` 행 읽기** ← read-side 핵심 (CLAUDE.local 이월분)
- crazy → **auto-inhibit severity=critical → 자동 HOLD → 승인 스크랩** 경로
- ⚠️ 의존: `y_thresholds` — init.sql에 **TEMP 존재**(`p99`=B9 crazy 기준)라 read-side 배선 가능 · **공식 PM DDL 승인만 대기**(헌법 3-2)

입출력: joined 예측 + `y_thresholds` → crazy 판정 · HOLD
검증: 챔버별 임계로 판정 · P99 초과 시 HOLD 발동

### Step 6. 상관분석 → grouping·가중치 → combine 교체 — **공동**

작업(상관분석 플랜 P1~P5):
- Step 4 `contribution_log` + Scorecard 라벨로 데이터셋
- **P1 구조겹침**(계층 A) + **P2 관찰상관** → **P3 통제주입**(계층 B 인과) → **P4 독립검증** → **P5 ablation**
  - 축 내부 상관: SPC(A1)=B · AE(A3)=A / **cross-channel(B1·B2·B3)=공동**
- 산출: grouping·집계함수(max/net/포화)·**최적 가중치**
- **combine 교체**: `naive_sum → grouped_2stage` (서브함수 불변, `combine` 내부만)
- **P6 가드·재검증** 훅(미탐 0 · regime trigger)

검증: 2단집계가 naive 대비 오탐↓ · 미탐 0

### Step 7. 정기 리캘리 라이브 트리거 — **B** (A 무관 · 같은 컨슈머, collector와 병렬)

> 로드맵(2026-07-24): 엔진(B4-3 `recompute_group`)은 완료, **상류 트리거 배선만 미완**. 같은 컨슈머라 B4-1 라이브 마무리에 묶는다.

작업:
- **주기 호출 배선**: 컨슈머가 매 `recalc_interval_wafers`마다 `recompute_group` 호출 → PROPOSED/auto 관리선 생성
- **ⓐ 무이상 게이팅**: 이상(alert/incident) 없는 구간에서만 자동 적용 (헌법 1-1 예외 — 상한 내 + `limit_corrections` 이력 기록 조건, `trigger_type='periodic'`)
- **ⓑ `control_limits_loader` trigger_type 노출 + reference 리로드**: periodic 활성 행이 **TTTM reference 오염하지 않게** (현재 미배선이라 무해하나, periodic 활성화 시 필수 — B4-2→B4-3 미완 action item)
- 중복 가드(`record_proposed` 중복 방지)

입출력: 주기 트리거 → `recompute_group` → PROPOSED 관리선(auto 적용 or 승인)
검증: N wafer마다 트리거 · 무이상 게이팅 동작 · reference 미오염

## 4. 착수 전 A와 정할 포인트

1. **collector 파일 소유** — B가 골격, A가 예측 조인·AE축 기여 (제안) vs 공동 파일
2. **예측 결측 정책** (Step 3) — 대기(타임아웃) vs AE축 0으로 진행
3. **combine 인터페이스** — 위 §2 축별 서브함수 방식 확정

## 5. 진행 순서 (병렬 → 합류)

```
[병렬]  Step 2 (A: 예측 캐시)   │   Step 3 뼈대·score_spc/tttm (B)
               └──────── 조인 정책 합의 ────────┘
                          ▼
        Step 4  combine(naive) + 계측  [공동]  ← score_ae/pred(A) 끼움
                          ▼
        Step 5  억제(get_phase)·발행·적재  [B]  → E2E 관통
                          ▼
        Step 5b B9 crazy wafer  [B]      (y_thresholds 승인 후)
                          ▼
        Step 6  상관분석 → grouped 교체  [공동]

[B 병렬 트랙]  Step 7 정기 리캘리 트리거  ── 같은 컨슈머, collector와 독립 진행 가능
```

- **Step 2(A)·Step 3(B) 병렬 착수** → 조인(Step 3)에서 합류
- naive로 **Step 5까지 먼저 관통**(작동 MVP + 분석 계측기) → Step 6에서 정교화
- **Step 7은 B 단독 병렬** — collector 체인과 의존 없음, 같은 컨슈머라 라이브 마무리에 함께
