# Context Score 요소 그룹핑 · 상관 근거 (v1)

> **생성**: 2026-07-23 · 담당 B(에이치) · B4-1 워킹 레퍼런스
> **소스**: `docs/Context_Score_알람_게이트_설계_v1.md`(§3 확정 4축 · §4 배점 가안) + `config/params.yaml`(B7) + 헌법 1-2·1-4 + 본 폴더 3종(넬슨·TTTM·ae_v3)
> **한 줄**: Context Score는 가점 **선형합산**인데, "합산"은 요소가 **서로 독립**임을 전제한다. 실제로는 여러 가점이 *같은 스트림에서 파생*되거나 *한 물리원인으로 동시에* 켜진다. 그 "서로 영향가는" 요소들을 묶어, 그룹 내부는 합산 대신 **집계(max/포화)**, 그룹 간만 합산하자는 문서다.

## 0. 왜 그룹핑이 필요한가 (문제 정의)

설계 문서 §3의 핵심 논리:

> "원천 ①(통계 소음)은 축 1개만 걸리고, 진짜 사건은 **여러 축이 동시에** 걸린다. '감지 채널 수렴'이 점수의 물리적 의미다."

즉 Context Score의 정당성은 전적으로 **"합산되는 요소가 독립 증거"라는 가정**에 의존한다. 이 가정이 깨지면:

- **이중·삼중 계상**: 한 센서가 드리프트하면 N1·N3·지속성·위반크기가 *한 사건에서 동시에* 터진다. 이걸 다 더하면 축 1개짜리 소음이 게이트(31)를 넘는 고득점이 된다 → **오탐이 Agent를 깨움**.
- **가짜 수렴**: PM 후 레짐 이동 하나가 Nelson 추세·AE drift·TTTM을 동시에 올린다. "3채널 수렴 = 고득점"으로 보이지만 원인은 3개가 아니라 **1개**(기준선 노후)다 → 점수는 높은데 진짜 개입 대상은 아님.

그래서 **"서로 영향갈 만한 요소"를 먼저 묶는다.** 원칙:

```
그룹 내부(상관 있음)  → 선형합산 금지, 대표값 집계 (max / 포화 / net)
그룹 간(독립)          → 합산 = 진짜 "채널 수렴" 점수
```

## 1. 대상 요소 전수 (배점 가안 §4)

| # | 요소 | 소스 | 성격 | 방향 |
|---|---|---|---|---|
| e1 | 룰 기본점 (N1 단발 / N2·N4 / N3 추세 / N5~N8) | B Nelson 엔진 | 단일센서·시간축 | + |
| e2 | 지속성 (연속 윈도우 유지 +10) | B Nelson 엔진 | 단일센서·시간축 | + |
| e3 | 위반 크기 (초과 σ당 +5) | B Nelson 엔진 | 단일센서·시간축 | + |
| e4 | TTTM score (≥2.0 +15 / ≥3.0 +30) | B TTTM (fleet median) | 챔버·공간축 | + |
| e5 | reference_suspect (=true −20) | B TTTM 역방향 룰 | 챔버·공간축 | − |
| e6 | AE Anomaly (`ae_raw`/`ae_score` z) | A `fdc.prediction` | 다변량·순간 | + |
| e7 | AE Drift (`ae_drift_score` 밴드) | A `fdc.prediction` | 다변량·누적 | + |
| e8 | predicted_c65 (P95 방향 가중) | A 예측치 | 품질 하류 | + (가중항) |
| m1 | 과도 윈도우 할인 (합산 후 ×0.5) | B (C42=1) | 전역 modifier | × |

## 2. 그룹핑 — 2계층

**계층 A = 소스 종속** (정의상 상관: 같은 스트림/같은 산식에서 파생 → 항상 함께 움직임)
**계층 B = 공통 물리원인** (채널은 독립이나, 특정 원인이 여러 채널을 동시에 켬 → regime 의존 상관)

### 2-A. 소스 종속 그룹 (within-channel)

#### A1 · 단일센서 SPC 다발 = { e1 룰점 · e2 지속성 · e3 위반크기 }

| 묶는 근거 | 내용 |
|---|---|
| 같은 물리 스트림 | 셋 다 **동일 (챔버×센서×step×window) 스트림 1개**에서 나옴 (넬슨 §1: control_limits 유니크 키). |
| 정의상 동반 상승 | 한 센서가 드리프트하면 N1(점 이탈)·N2(연속)·N3(추세)가 **동시** 위반 + 그만큼 오래 지속(e2) + 이탈 폭 증가(e3). 하나의 물리사건이 4~5개 가점으로 분할된다. |
| 룰 간 상관 | Nelson N1~N8은 서로 독립 검정이 아니다 — ARL 문헌(Montgomery)에서 8룰 중첩 시 오탐이 룰 수만큼 곱해지지 않고 상관 때문에 ARL₀ 370→92로 뭉친다(설계 §1-2 ①). 룰별 점수 선형합산은 이 상관을 무시. |

→ **집계 권고**: 그룹 내부는 **대표 룰 1개 점수 + (크기·지속) modifier**로 포화. 위반한 룰 개수를 그대로 더하지 않는다.

#### A2 · TTTM 공간축 양면 = { e4 score(+) · e5 reference_suspect(−) }

| 묶는 근거 | 내용 |
|---|---|
| 같은 fleet 비교의 앞·뒷면 | e4는 "내 챔버가 형제(fleet_median) 대비 벌어졌나", e5는 "그 형제(fleet) 자체가 오염됐나". **동일한 TTTM 산식**의 두 해석(TTTM §2·§4). |
| 배타·보정 관계 | e5=true면 fleet_median이 공통원인으로 끌려간 상태 → e4는 오히려 **작게 나온다(놓침)**. 그래서 e5는 e4를 **보정(감점)**하는 항이지 독립 가점이 아니다 (TTTM §4: "다수 동시 이탈 = 기준 오염 → 감점 방향"). |
| 래칭 방지 공유 | 둘 다 같은 σ_ref·center 재료를 쓰고, e5는 조건 풀리면 discard — e4와 상태를 공유. |

→ **집계 권고**: 한 축에서 **net 산출** (`e4 − (e5면 페널티)`). e4·e5를 독립 슬롯 2개로 세지 않는다.

#### A3 · AE 다변량축 = { e6 Anomaly · e7 Drift }

| 묶는 근거 | 내용 |
|---|---|
| 불가침 12 (단일 계약) | e6·e7은 **모두 단일 `ae_raw` 하나에서 파생**된다. `ae_raw → ae_score(순간) → EWMA → ae_drift_score(누적)`. 별도 모델 없음 (ae_v3 §3·불가침 12). |
| 순간 vs 누적 상관 | e7은 e6이 만든 `ae_score` 스트림의 EWMA다. 레짐 전환 시 **둘 다 켜진다**(ae_v3 §3.4 상보표: 레짐전환 = 채널1·2 동시 ✅). 같은 원신호의 시간필터 차이일 뿐. |
| 스케일 종속 | e7의 유효 밴드폭이 **0.07(B0 0.13~ALARM 0.20)**로 좁아 포화가 쉽다 — e6가 크면 e7도 빠르게 1.0 포화 → 독립 가점처럼 더하면 이중계상. |

→ **집계 권고**: 그룹 내부는 **순간(e6)·누적(e7) max** 또는 "스파이크는 e6만 / 느린 드리프트는 e7만"의 상보 라우팅(ae_v3 §5.1). 둘을 선형합산 금지.

### 2-B. 공통 물리원인 그룹 (cross-channel · regime 상관)

> 계층 A와 달리, 이 그룹들은 **채널 자체는 독립**이다(그래서 수렴 시 고득점이 정당). 다만 **하나의 물리원인**이 여러 채널을 동시에 켜므로, 점수만으로 "채널 수 = 원인 수"라 읽으면 오판한다. → 점수는 게이트 통과용이고, **원인 분기는 Supervisor 4지선다**가 한다(헌법 1-4).

#### B1 · "느린 레벨 이동 / 레짐" 수렴 = { e1의 N3 추세 · e7 AE Drift · e4 TTTM score }

- **근거**: PM 후 레짐 이동·기준선 노후·완만 sub-σ 드리프트 **하나**가 세 축을 동시에 올린다. N3=단일센서 시간축 추세, e7=다변량 누적 드리프트, e4=공간축 레벨 갭 — 모두 "느린 이동"에 반응.
- **함의**: 이 수렴은 "고장"일 수도, **"기준선 노후"(원천 ④)** 나 **공통원인**일 수도 있다. → 점수는 높게 나오는 게 정상이나, **가한계 Phase(생성 억제)·reference_suspect·Supervisor 원인분기**가 오원인을 흡수해야 한다. 점수 배점 단계에서 세 축을 완전 독립으로 과대 가중하지 말 것.

#### B2 · "대형 단일센서 스파이크" 중첩 = { e3 위반크기(N1 계열) · e6 AE Anomaly }

- **근거**: 큰 단일센서 이탈은 재구성 잔차 `r=x−AE(x)`를 키워 `ae_raw`(e6)도 함께 올린다. → e3와 e6이 **부분 상관**.
- **부분 종속(완전 아님)**: AE의 고유 가치는 *각 센서가 한계 안인데 조합이 낯선* 다변량 붕괴(설계 Q7: C31 정상·C11만 얕음, 상관 −0.978 붕괴)다. 이 경우 e6만 켜지고 e3는 안 켜짐 → 완전 종속은 아님.
- **집계 권고**: 큰 N1 + AE anomaly를 완전 독립 2채널로 보면 스파이크 **과대평가**. e6가 "e3로 설명되는 부분"과 "다변량 고유 부분"을 구분(예: `ae_top_channels`가 N1 위반 센서와 일치하면 할인).

#### B3 · "공통원인 4챔버 동시" 상쇄 = { e5 reference_suspect · 4챔버 동시 e1/e7 }

- **근거**: 같은 장비의 4챔버는 트랜스퍼 모듈·유틸리티를 공유 → 참조/유틸 공통원인이면 4챔버가 **동시에** Nelson·AE·TTTM을 켠다(설계 §1-2 ⑤). 이건 개별 챔버 고장이 아니라 **참조 오염**.
- **집계 권고**: e5=true는 이 상황의 신호 → **감점 방향**이 맞다. 4챔버에서 동시에 올라온 e1/e7 가점을 "4배 증거"로 합산하면 안 됨 (Incident 그룹핑·헌법 1-4가 챔버축 병합, e5가 점수축 상쇄).

### 2-C. 종속 가중항 (독립축 아님)

#### predicted_c65 (e8)

- **근거**: A 모델이 **같은 `fdc.raw` 센서**로 낸 하류 산출 → 모든 센서기반 채널(e1·e4·e6·e7)과 **상류(입력)를 공유**한다. 독립 증거가 아니다.
- **규칙(설계 §6·Q5)**: **단독 발동 불가**(가중항만), **가한계 Phase 0~1 가중 자동 0**(재학습 전 예측 불신), 가중치 자체가 `context_score_pred_weight: null`(B4-1 확정 전). → 그룹 밖 **곱/가중 modifier**로만 취급, 합산 슬롯에서 제외.

#### 과도 윈도우 할인 (m1)

- **근거**: 점화 과도(C42=1) 구간에서 온 신호(주로 e1·e6)에 걸리는 **전역 modifier(×0.5)**. 독립 요소가 아니라 A1/B2 신호의 **출처(window)에 종속**. → 그룹 집계 **후** 적용하는 스칼라.

## 3. 권고 산출 구조 — 2단 집계

```
[1단: 그룹 내부 집계]  상관 있는 요소 → 대표값으로 뭉침 (합산 금지)
   A1  단일센서 SPC   = 대표룰점 ⊕ 크기·지속 modifier      (포화)
   A2  TTTM 공간축     = score − (reference_suspect 페널티)  (net)
   A3  AE 다변량       = max(anomaly, drift) 또는 상보 라우팅 (max)

[2단: 그룹 간 합산]  독립 채널의 수렴 = 진짜 점수
   context_raw = w1·A1 + w2·A2 + w3·A3
   context_score = clip( context_raw × (과도면 0.5) + pred_weight·e8_dir , 0, 100 )
                                         └ m1 (전역)     └ e8 (가중항, Phase0~1=0)

[게이트]  ≥ context_score_agent_min(31) → Agent / critical·manual → 우회
```

**설계 §3 4축과의 매핑**: 축① = A1, 축② = A2, 축③ = A3(drift 확정·anomaly는 A 제안), 축④ = e8(가중항). → **"독립 4축 수렴"이 2단 합산에만 반영**되고, 각 축 **내부의 상관은 1단에서 흡수**된다.

## 4. 요소 상관 요약 (한눈에)

| 요소쌍 | 상관 유형 | 그룹 | 처리 |
|---|---|---|---|
| e1 ↔ e2 ↔ e3 | 같은 스트림 파생 (강) | A1 | 대표값 집계 |
| e4 ↔ e5 | 같은 산식 앞뒷면 (강, 배타) | A2 | net |
| e6 ↔ e7 | 단일 ae_raw 파생 (강) | A3 | max/상보 |
| e1(N3) ↔ e7 ↔ e4 | 공통원인 "느린 이동" (중, regime) | B1 | 축 독립 유지 + 원인분기 |
| e3(N1) ↔ e6 | 대형 스파이크 잔차 (중, 부분) | B2 | e6 할인 |
| e5 ↔ 4챔버 e1/e7 | 공통원인 참조오염 (중) | B3 | 감점·Incident 병합 |
| e8 ↔ 모든 센서 채널 | 상류 입력 공유 (하류 종속) | 2-C | 가중항·단독불가 |
| m1 ↔ 과도출처 e1/e6 | 출처 종속 | 2-C | 전역 ×0.5 |

**독립(안전하게 합산 가능)**: A1 ⟂ A2 ⟂ A3 — 시간축(자기 센서 이력) vs 공간축(형제 챔버) vs 다변량(센서 조합)으로 **감지 사각이 서로 다르다**. 이게 "수렴이 의미 있는" 이유이자 2단 합산의 정당성.

## 5. 미결 · 검증 · 플래그

- **배점·가중(w1~w3·pred_weight)은 B4-1에서 B 확정** — 본 문서는 *어떻게 묶고 왜 묶는지*(구조)만 확정. 수치는 Scorecard 실측 튜닝, 기준 = **미탐 0 유지 하 호출 최소화**(설계 §6).
- **집계 함수 선택(max vs 포화합 vs soft-OR)**: 1단 내부 집계를 max로 할지 완만 포화로 할지는 실데이터 오탐/미탐 채점 후 결정.
- **⚠️ 라벨 정합 이슈(발견)**: 설계 §4 배점표는 "**AE Drift** z≥2→+15/z≥3→+25"로 적었으나, `ae_v3` §5.4는 **z 채점은 Anomaly(`ae_raw`)** 몫이고 **Drift는 [0,1] 밴드**(">z 쓰지 말 것", 이미 포화된 값)라고 명시 — **둘이 뒤바뀜**. 그룹핑엔 영향 없으나(둘 다 A3), B4-1 배점 확정 전 **§4 표기 정정 필요**. → e6(z)·e7(밴드)로 분리 표기 권장.
- **Nelson 룰 프루닝(설계 §6 ⓒ)과 연동**: A1 내부 상관이 큰 근거가 곧 "기여 없는 룰 비활성"의 근거 — 프루닝 결과가 A1 대표룰 집계 방식에 반영되어야 함.
```
