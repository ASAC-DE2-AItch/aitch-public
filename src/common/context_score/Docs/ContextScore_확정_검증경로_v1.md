## 1. 무엇을 확정했나

```
스트림 점수 = e1 + e3
              │    └─ σ가산 × (관리선 초과폭 ÷ σ)
              └────── 그 스트림에서 터진 룰 중 최고 배점 (룰 간 max)

최종 점수 = 최고 스트림 + (나머지 스트림 합) × damping   → 게이트 31 과 비교
```

| 손잡이 | params 키 | 확정값 |
| --- | --- | ---: |
| N1 배점 | `context_score_rule_base.N1` | **20** |
| run 룰 배점 | 〃 `.N2`~`.N8` | **8** |
| σ가산 | `context_score_size_per_sigma` | **2** |
| 스트림 간 damping | `context_score_stream_damping` | **0.2** |
| 게이트 | `context_score_agent_min` | **31 (불변)** |
| 룰 간 집계 | (코드) | **max — 유지** |

**전제**: AE(e6·e7) = 0 · TTTM(e4·e5) = 0 · e2 미배선 · `pred_weight: null`
→ **점수를 내는 축은 SPC(e1+e3) 하나뿐**이다.

## 2. 검증 경로 — 5단계

### 단계 1. 축을 격리해 변수를 없앴다

G8 원칙은 *"배점이 바뀌면 임계가 무효"* 라, 살아 움직이는 축이 있으면 아무것도 확정할 수 없다.
네 축을 각각 판정해 **점수에 도달하는 축을 SPC 하나로 고정**했다.

| 축 | 판정 | 근거 |
| --- | --- | --- |
| e6·e7 AE | **0 격리** | 번들 포화 — 오프라인 대칭 검증에서 seg 불일치 + 노이즈 과적합(0.01σ 추가에 100% 포화). 라이브 41% 잔존 |
| e4·e5 TTTM | **0 격리** | C62 자 왜곡 (2026-08-05 합의). 경로② fleet 정규화는 별도 조사 후 기각 |
| e8 pred | **null** | 예측 모델이 학습 분포 밖에서 외삽하지 않음 — 4~10σ 부스트 20조합 전부 P99 미달 |
| e2 지속성 | **미배선** | 위반 dict 에 지속성 필드 없음 (단계 5 에서 재검토·기각) |

> 격리는 **조건부**다. 축이 하나라도 되살아나면 총점 스케일이 바뀌어 §1 전체가 무효다(§4).

### 단계 2. 5차원 전수 탐색으로 조합을 골랐다

배점 3키 × damping × 게이트를 함께 쓸었다. **게이트를 안 건드리는 조합 중 최선**을 채택했다 —
게이트를 바꾸면 C 쪽 fixture·계약까지 번지기 때문이다.

입력 = joined 덤프 5종 **13,951 wafer**(라벨 시나리오 SC1~SC5), 관리선 시딩 180행·4챔버.

| 시나리오 | 구 배점 | **선택 A** |
| --- | ---: | ---: |
| SC1 drift 단일센서 | 0% · +12장 | 1% · +12장 |
| SC2 spike | 0% · +91장 | 0% · **+16장** |
| SC3 multi 공통이동 | 6% · +8장 | **61%** · **+2장** |
| SC4 storm 3센서 | 16% · +4장 | **93%** · **+2장** |
| SC5 oscillation | 0% · **+511장** | **12%** · **+2장** |
| 헛호출 | 1.4건/일 | 3.0건/일 |

*(주입 wafer 게이트 통과율 · 첫 탐지 지연)*

핵심은 **damping** 이다. 기존 max 집계는 *"여러 센서가 동시에 걸렸다"* 는 수렴 증거를 버렸다 —
다센서 사건에서 발화 스트림이 평균 **7.96개**인데 1개만 점수에 반영돼 첫 통과가 **62장 지연**됐다(T14).

### 단계 3. 라이브에서 오프라인 예측을 확인했다

단계 2 는 덤프 재채점이다. 같은 결론이 라이브에서도 나오는지 한 라운드 돌렸다.

**조건**: SC3(`multi_chamber_common_c17` · 3챔버 C17 3σ) · DB 초기화 + 컨슈머 재기동 후 · 시연 속도 · 2,800 wafer

```
주입 챔버  SIM_CH_1 59.9% · SIM_CH_2 63.5% · SIM_CH_4 64.7%   →  평균 62.7%
비주입     SIM_CH_3  1.6%                                      →  39배 분리
첫 탐지 +1장 · 헛호출 3.6건/일
```

**오프라인 예측 61% vs 라이브 62.7%** — 덤프 재채점이 유효한 대리 측정이었음이 확인된다.

### 단계 4. 하류 도달을 확인했다

점수가 맞아도 하류에 안 실리면 의미가 없다. LLM 직전까지 따라갔다.

```
reference_suspect   True 2,049 / False 14   (99.3%)   ← "다 같이 움직임" = 공정·기준선 쪽
suspect_sensors     ["C17"]                            ← 주입한 그 센서
AlertModel 파싱     2,063 성공 / 0 실패
R2R tuning 산출     1,032건
```

> ⚠️ **LLM 실물은 미확인** — `agent-service` 이미지 미빌드 + 엔드포인트 미설정.
> 확인 범위는 **파싱·툴 입력 산출까지**이고, *"LLM 이 그 근거로 R2R 을 1순위로 쓴다"* 는 검증되지 않았다.

### 단계 5. 대안 4종을 실험해 전부 기각했다

*"더 잘할 수 있지 않나"* 를 네 방향으로 흔들었다. 전부 같은 입력·같은 게이트(31)로 재채점했고,
**현행 재현이 운영 `context_score()` 와 전 wafer 완전 일치**함을 매 실험에서 자기검증했다.

| 대안 | 첫 탐지 | 주입통과 | 헛호출/일 | 기각 사유 |
| --- | --- | ---: | ---: | --- |
| **현행 (선택 A)** | 기준 | 41.8% | **3.1** | — |
| ① e2 지속성 가산 | **0 개선** | 56.9% | 4.4 | 밀도가 쌓여야 발동 → **정의상 후행**. 미탐→탐지 전환 0건. 위반 dict 계약 변경 필요 |
| ② 지속성 룰 배점 인상 | SC1 −10장 | 47.7% | **21.6** | 단독 통과에 배점 31 필요 → **N1(20)을 가림**(설계 반전). 헛호출 7배 |
| ③ zone 룰 e3 부여 | SC1 −5장 | 48.3% | 12.3 | **유일하게 부작용 없음** — 다만 헛호출 4배. 발표 후 과제로 이월 |
| ④ 룰 간 max → 합산 | **0 개선** | 46.8% | 10.7 | 동시 발화가 5.6% 뿐이고 그중 76% 가 **존이 포개진 쌍** = 중복 계상 |

**단계 5 에서 새로 확정된 것 — 룰 간 max 의 근거 교체**

기존 근거는 문헌 인용이었다(*"Nelson 룰은 상관이 깊다 — Montgomery ARL₀ 370→92"*, 그룹핑 문서 A1).
우리 데이터는 그 전제와 다르다:

```
한 스트림 동시 발화 룰 수:  1개 94%  ·  2개 6%  ·  3개 0.4%
평균  정탐 1.06개  vs  오탐 1.07개      ← 정탐이 더 뭉치지 않는다
```

즉 **상관이 얕다**. 그런데도 max 가 맞는 이유는 다르다 —
ⓐ 94% 가 단독이라 **합산의 실익이 없고** ⓑ 더할 것이 생기는 6% 는 **오탐 쪽이 더 많으며**
ⓒ 그 동시 발화의 76%(1,748/2,313)가 `N1 ⊃ N5 ⊃ N6` 처럼 **존이 포개진 쌍**이라 합산이 곧 중복 계상이다.

> 결론은 같고 **근거만 바뀌었다.** 그룹핑 문서 A1 의 논거를 위 실측으로 갱신할 것.

## 4. 무효화 조건 — 이 문서가 죽는 시점

1. **AE(e6·e7)가 점수에 도달하면** — 총점 스케일이 바뀌므로 §1 전체 재측정·재확정. 자동 무효다.
2. **TTTM(e4·e5) 격리가 풀리면** — 위와 동일.
3. **게이트(31)를 건드리면** — 배점–임계는 세트다. 한쪽만 바꿀 수 없다.
4. **관리선 정본이 바뀌면**(재시딩·σ 재보정) — 모든 σ 기준 수치가 다른 자가 된다.

## 5. 남은 한계 — 함께 읽을 것

- **살아 있는 축이 하나뿐이다.** e2 미배선 · e4·e5·e6·e7 격리 · e8 null. 발표는 이 상태로 간다.
- **LLM 실물 미검증** (단계 4) — 파싱·툴 입력까지만 확인.
- **Incident 층 미측정.** 전 실험이 wafer 층 + 첫 탐지까지다. 게이트 통과가 늘어도
  `_incident_has_brief` 가 Brief 있으면 skip 하므로 **추가 LLM 호출로 이어진다는 보장이 없다**.
- **SC1·SC2 는 통과율이 낮다** (1% · 0%). 단일 센서 1스트림이라 수렴 증거가 없어서다 —
  배점 문제가 아니라 축 구성의 문제이고, 단계 5 ③(zone e3)이 그 후보다.
- **대안 실험의 표본 한계**: ③ 의 정탐 표본이 N6 80건·N8 101건으로 얇고, N2·N3·N4·N7 은
  오프라인 값 커버리지가 15~34% 라 스코프에서 뺐다. 실제 구현 시 결과가 달라질 수 있다.
