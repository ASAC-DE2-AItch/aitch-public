## 1\. 큰 그림

Context Score 로직을 **공용 모듈**(`src/common/context_score/`)에 두고, `context_score`를 **축별 순수 서브함수**로 쪼갠다. 각자 자기 축 함수만 채우고 `combine`만 공동. 이렇게 하면 같은 브랜치에서도 **서로 다른 파일을 편집**하니 충돌이 없어.

```
context_score(joined):
    s1 = score_spc(violations)      # B
    s2 = score_tttm(tttm)           # B
    s3 = score_ae(prediction)       # A
    s4 = score_pred(prediction)     # A
    return combine([s1,s2,s3,s4])   # 공동
```

collector(합치는 로직)는 `joined`를 만드는 데서 **멈추고**, 점수 매기기는 별도의 얇은 오케스트레이터가 네 함수를 dispatch해. 그래서 A 함수가 다른 파일에 있어도 문제없어.

> **(2026\-07\-28 추가)** 이 네 축은 라이브 루프에서 `collector → context_score → publisher` 체인의 한가운데에 놓인다. 체인 어디서 예외가 나도 SPC 기록·offset 커밋이 죽지 않도록, **축 함수는 raise하지 않는 total function**으로 계약을 못박는다 (§4\-③ · §9 P1).

## 4\. 인터페이스 계약 — 병렬 작업의 핵심

우리 둘이 서로 코드 안 건드리고 병렬로 가려면 **이것만** 맞추면 돼. (①②는 원안, ③④는 2026\-07\-28 개정안 반영분)

**① `joined` 이벤트 스키마** (collector가 만들고, 네 함수가 각자 자기 필드만 읽음)

```
joined = {
  wafer_id, chamber_id, ts,
  violations[],          # B — Nelson 위반 dict 전체 (current_value·관리선·sensor_window 포함)
  tttm,                  # B — chamber_rollup {score, top_gap_sensor, reference_suspect, ...}
  prediction,            # A — {predicted_c65, drift_score, anomaly_score, shap_top3, is_qual}
  is_transient,          # C42 과도 플래그 (m1 ×0.5 할인용)
  is_qual                # prediction에서 승계 (가드 포함)
}
```

**② 서브함수 시그니처** (내부 구현은 서로 몰라도 됨)

```
def score_ae(prediction: dict, cfg) -> float   # 부작용 없음(순수)
def score_pred(prediction: dict, cfg) -> float  # 단독불가·Phase0~1 가중 0
```

`combine`이 naive\_sum → grouped\_2stage로 바뀌어도 **서브함수 시그니처는 불변**이라 우리 함수는 안 건드려도 돼.

**③ 축 함수 total function 계약** *(2026\-07\-28 신설 — 개정안 §1\-2)*

> **축 함수 4종은 어떤 입력에도 raise하지 않고 반드시 float을 반환한다.**

- 결측·비수치·타입 이상은 **0.0 반환 + `logger.warning`**으로 흡수한다. 예외를 위로 던지지 않는다.
- 값 검증 시 `float()` 직행 대신 타입 가드를 먼저 둔다. **bool 제외 필수** — `float(True)=1.0`이 조용한 오계산을 만든다.
- 위반 dict 등 중첩 구조는 **직접 인덱싱 금지, `.get()` \+ None 가드**. 키 하나 결측이 wafer 전체 alert을 죽이지 않게.
- 이 계약은 **테스트로 강제**한다 (`tests/test_axes.py` — 비정상 입력 케이스 필수).
- 계층 방어: **축 가드 = 1차 방어**, consumer의 호출 격리(§9 P1\-1) = 최후 방어. 둘 다 둔다.

**④ 런타임 주입 키는 `build_joined()` 이후에** *(2026\-07\-28 신설 — 개정안 §2\-4)*

- `collector._normalize_prediction`의 `_PREDICTION_KEY_MAP`은 **화이트리스트**다. `score_pred`가 읽는 런타임 주입 키(`phase`·`p95_threshold`)는 normalize를 통과하지 못한다.
- 따라서 주입은 반드시 **`build_joined()` 이후** `joined["prediction"]` dict에 한다. (대안: 맵에 passthrough 추가 — 이 경우 B 협의 필요.)
- 오케스트레이터(`context_score.py`) 구현 시 이 순서를 지키지 않으면 pred 축이 조용히 0이 된다.

### 9\-1. P1 — 라이브 전 필수

**① collector 호출 예외 격리** (`spc_consumer._process_wafer`, B 소유)

collector 호출은 라이브에서 **체인 전체**다. 예외가 나면 ⓐ `_persist_tttm`(TTTM 이력 적재)이 건너뛰어지고 ⓑ `_flush`의 except로 빠져 **offset 커밋도 안 됨** → 재시작 시 대량 리플레이. 같은 함수의 nelson/tttm `feed`는 이미 개별 격리돼 있는데 collector만 노출돼 있다.

```python
if self.collector is not None:
    try:
        self.collector((wafer_id, chamber_id, ts, violations, tttm_obj))
    except Exception:
        logger.exception("collector/score 체인 실패 — SPC 적재는 계속: %s", wafer_id)
self._persist_tttm(tttm_obj)
```

**트레이드오프 합의 필요**: 격리하면 그 wafer의 alert은 유실(best\-effort), SPC 기록·커밋은 보전. 미격리는 반대(재시도 가능하지만 결정적 버그면 커밋이 영영 뒤처짐). 권고는 **"SPC 기록 = must, alert = best\-effort \+ 실패 카운터"** — 실패 wafer\_id 카운터/메트릭으로 유실을 추적한다.

**② 축 함수 입력 가드** — §4\-③ 계약의 구체 반영.

- `score_pred`: `float(predicted)`·`float(p95_threshold)` 앞에 수치 검증(bool 제외) → 비수치면 `0.0` \+ warning.
- `score_spc._exceedance_sigma`: `v["control_limit_upper"]` 직접 인덱싱 → `.get()` \+ None 가드, 해당 위반만 e3=0 처리(\+warning).

**③ `prediction_cache.get()` 깊은 복사**

현재 `{k: v for ...}`는 **1단계만 사본**이라 `shap`(list of dict) 같은 중첩 객체는 참조 공유 → 하류가 변조하면 캐시 원본이 오염된다. **권고: `copy.deepcopy(entry)` 후 `_read` 제거** (wafer당 1회·shap 3개라 비용 무시 가능). 대안 ⓑ upsert 시 `shap`을 tuple로 저장(복사 0, 하류 list 기대 시 마찰) / ⓒ "반환 dict는 read\-only" 문서 명시(강제력 없음).

### 9\-2. P2 — 권고

- **2\-1 예측 조인 레이스**: A의 예측 발행과 B의 wafer flush가 **같은 신호**(다음 wafer 첫 row)로 트리거된다. B의 조인은 poll 루프에서 즉시 실행되는데 A의 예측은 [A poll → 추론 → produce → broker → B poll] 왕복을 거치므로 **wafer N의 조인이 N의 예측보다 먼저일 확률이 높다** → AE/pred 축 상시 0 가능. **1순위 권고: collector에 hit/miss 카운터 추가 → 리허설 실측 후 결정.** 대안 ⓑ 조인 짧은 유예(수 초 재시도) / ⓒ A 발행 조기화(A 파이프라인 변경 필요). TTL 900s는 이 레이스와 무관(레이스는 초 단위).
- **2\-2 config 병합 순서**: `config.py`가 pred 3키(`..._pred_p95_scale`·`_w_cap`·`_gated_phases`)를 하드 요구 → params.yaml 병합 전 브랜치에서 `load()` 자체가 실패. **코드는 유지**(헌법 6\-1 정합, 조용한 기본값 금지) 하고 **브랜치 병합 순서를 config 먼저로** 못박고 `config_파라미터_합의안` doc\-sync 티켓을 건다.
- **2\-3 ISO timestamp 파싱**: `prediction_cache._extract_ts`가 수치만 허용하는데 A producer는 `timestamp`를 **ISO\-8601 문자열**로 발행 → 항상 수신시각 fallback(ts 역전 방어가 "도착순"으로 동작). 권고: `datetime.fromisoformat(v.replace("Z","+00:00")).timestamp()` \+ try/except fallback 유지.
- **2\-4 주입 위치**: → **§4\-④로 승격**(계약화).

### 9\-3. P3 — 선택 (성능·로그 위생)

- `_enforce_capacity`가 full 상태 upsert마다 O(n) min 스캔 — max\_entries=5000·231 wafer/day에선 무해. **대량 replay/백필 시에만** 문제. 필요 시 heapq/OrderedDict LRU. 현 규모 보류 권고.
- `score_spc` 미등록 rule\_id 경고가 wafer마다 반복(알람 폭풍 시 스팸) — 모듈 레벨 `set`으로 최초 1회만 warning.
- `collector` 예측 결측 INFO — 2\-1ⓐ 카운터와 세트로 debug 강등 or N건당 1회 요약.
- `_ever_read` 재시작 리셋은 **의도된 동작**(브링업 폭주 방지). 수정 불요 — "재시작 직후 구간의 진짜 stranded는 WARNING이 안 찍힘"을 운영 문서에 명시.

### 9\-4. 무결 확인 (리뷰 완료·문제 없음)

`score_tttm`(None/빈 dict 가드·순수성) · `score_spc` 스트림별 집계와 스트림 간 max(이중계상 방지)·σ≤0 가드 · `score_pred` 게이트 순서와 오설정 명시 에러 · `prediction_cache` ts 역전 방어·형식오류 skip·RLock·TTL/용량 null 처리 · `spc_consumer` 예외 격리·역직렬화 skip(6\-2)·graceful shutdown·at\-least\-once 커밋(M1) · `collector.build_joined` 순수성·결측 진행(★③)·is\_qual 승계 가드.
