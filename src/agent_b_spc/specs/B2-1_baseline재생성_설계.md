## 2. 2-track 산출물 스키마 (조합②)

**원칙**: `initial_limits.py`는 **모든 그룹에 대해 ±3σ와 분위수 경계를 둘 다 계산**한다. 어느 방식을
쓸지(`method`)는 KEEP\* 판정을 아는 `monitoring_whitelist.py`가 확정한다 — 두 스크립트의 역할 분리 유지.

### 2-1. `initial_limits_v1.csv` 컬럼 + ⚠️ 표본 규칙 (리뷰 R2-1)

| 컬럼 | 뜻 | 산출 표본 |
|---|---|---|
| `center`, `sigma`, `ucl`, `lcl`, `k_sigma` | ±3σ 관리선 (기존) | **트림 후** `trimmed` (양쪽 1% 트림) |
| `q_low`, `q_high` | 분위수 **레벨** = `0.00135` / `0.99865` (±3σ 등가, 고정) | (상수) |
| `q_lcl`, `q_ucl` | 그 레벨의 **경계값** (`np.quantile`) | **트림 전** `values` (최근 500) |

> **⚠️ 치명 주의 — 트림 표본 분리**: 현행 코드는 `values`(최근 500) → 1% 트림 → `trimmed`에서 σ
> 산출 구조다. **트림은 σ-track 전용이다.** `q_lcl`/`q_ucl`은 반드시 **트림 전 `values`** 에서
> 계산한다. 트림된 표본(양쪽 1% 절단) 위에서 0.135% 분위수를 구하면 경계가 트림 절단선에 붙어
> 자기표본 오탐이 오히려 ~2%(σ보다 나쁨)로 붕괴하고 DoD가 원인불명 실패한다. 근거 실측
> (`analysis/false_alarm_mechanism.py:47`)도 트림 전 원표본 `v`에서 `np.quantile` 호출.
> **참고(indicative) 수치**: 역사 실측 ±3σ 4.43% → 분위수 0.30%(README·브리핑)는
> `analysis/false_alarm_mechanism.py`가 **리셋 이후 C6_0 전체(~8,154장, 실험 갭 가로지름)**에서 낸 값이다.
> R1로 baseline이 **복귀 블록 최근 500장**으로 바뀌었으므로 표본이 다르다 → DoD 실검증은 재생성된 동일
> 표본에서 재산출한다(§6-1). 분위수 0.30%는 구성상(n×0.27%) 표본 무관하게 재현되나 **σ 값은 표본에 따라
> 달라질 수 있다**(갭·실험 前 블록 제외로 더 균질 → 낮아질 개연).
> **표본 민감성 명시**: n=500에서 0.135% 분위수는 사실상 최솟값~2번째 값 보간이라 표본에 민감하다
> (회의 주의 6과 동일 맥락). 시뮬레이터 증량 시 안정화.

### 2-2. `monitoring_whitelist_v1.csv` 신규 컬럼

| 컬럼 | 뜻 |
|---|---|
| `method` | `quantile` (decision=KEEP\*) / `sigma` (그 외) |

> **주의(R5)**: KEEP\* 집합은 C54·C56 정착 이동으로 **자동 확장될 수 있다**(§6 DoD②). `method=quantile`은
> KEEP\* 전체에 규칙적으로 붙으므로, 신규 KEEP\* 그룹도 분위수 대상이 된다 — DoD는 개수를 고정하지 않는다.

### 2-3. DB 시딩 시 매핑 (3단계 — 참고)

`control_limits` 적재 시 두 CSV를 그룹키로 join하여 `method`별로 확정한다:

- `method='sigma'`  → `ucl/lcl` = ±3σ, `k_sigma`=3.0, `q_low/q_high`=NULL
- `method='quantile'` → `ucl/lcl` = `q_ucl/q_lcl`(경계값), `q_low/q_high`=레벨, `k_sigma`=NULL, `sigma`=참고
- **시딩 대상**: `KEEP`·`KEEP*`만 (EXCLUDE/EXCLUDE?는 제외).
- **⚠️ 챔버 오프셋 시딩(회의 결정 6)**: 오프셋 평행이동은 **CSV 레벨이 아니라 시딩 단계**에서 한다.
  그 시점엔 위 매핑으로 `ucl/lcl`에 이미 (method별) 활성 경계가 접혀 있으므로, **method 무관하게
  `center`·`ucl`·`lcl` 3개만 오프셋 δ만큼 이동**하면 된다(`q_low`/`q_high`는 레벨이라 불변, `sigma`도
  병진 불변). → quantile 행의 `q_lcl`/`q_ucl`은 이미 `ucl`/`lcl`에 반영돼 별도 이동 불필요.

> 이 매핑은 upstream `db/init.sql`의 `control_limits` 스키마(method/q_low/q_high/k_sigma)와 정합.

    중앙값(≈166) 기준 밴드 밀도는 **25~29%** — 깨끗한 이봉(골)이 아니라 **광범위 다봉/광폭 skew**. modality
    게이트(band 0.10·valley 0.15)를 실데이터에 돌리면 `bimodal=False`(center_density 25.4/29.0%) → **타깃을
    못 잡는 dead code**. valley 임계를 올리면 정상 광폭까지 오탐 → **modality 게이트 폐기**(구현 Task 7 제거).
- **step4는 KEEP 유지 (회의 결정·데이터 정합)**: 회의가 정착 이동한 목적이 "정착 신호 감시"였고 데이터도
  step4=KEEP이라 정합. **다만 ±3σ 밴드가 광폭이라 self-FA 0% = 사실상 아무것도 안 잡는 무력한 관리선**이다.
  이는 "bimodal 제외" 문제가 아니라 **"비정규 광폭이라 ±3σ가 무력"**이라는 별개 이슈(wide_limits는 0-교차라 사각).
- **⚠️ 팀/W7 위임 (스코프 밖·구현이 조용히 결정 안 함)**: "step4 광폭 무력 + 과도 감시 제거"의 순효과는
  **C54/C56 실질 감시 약화**다. 처리 방향(ⓐ 과도 병행 유지=정착 이동 부분 철회 / ⓑ 무력 수용 / ⓒ 광폭 원인
  규명=std가 신호인지 두 위치 분산인지)은 **도메인 판단 → 설계/멘토·W7**. 기존 위임("W7 정착-only 미탐 시
  확장/재검토")대로 **step4는 일단 KEEP**, "광폭 무력 가능성"을 **W7 백로그**로 넘긴다.

**⚠️ 번복 (2026-07-12, PM 승인)**: 위 3-2 전체(정착 이동)를 번복한다. 근거였던 "정착 std≈과도 std"는
raw 3초 std 기준이었는데, 관리선이 실제로 쓰는 **wafer-mean** 단위로는 **정착 480 vs 과도 148(3~4배)** 로

## 5. 죽은 코드 정리 (C6_1 제외의 파급)

C6_1(유일한 소표본 n<100) 제외 후 복귀 블록만 쓰면 전 그룹 표본이 `ROLLING_N`(500) 도달 → 무발동.
**두 가드 제거는 반드시 C6_1 제외와 같은 커밋 ②** (커밋 ①에서 제거하면 C6_1 그룹이 트림돼 diff≠0 — §9):

- **`MIN_TRIM_N` 트림 가드 제거**: `if n_raw >= MIN_TRIM_N` 분기 삭제, 트림 항상 적용(σ-track만). 임계값 100은
  버리지 않고 **사전 게이트 임계 `cfg.min_trim_n`으로 재사용**(config 단일 소스, 헌법 6-1 — 하드코딩 금지).
- **`MIN_GROUP_N`/`low_n` QA 플래그 제거**: 미발동 죽은 코드. 소표본 가드는 라이브 재산정(B4-3) 책임.

**선검증 게이트 2종 (성격 구분 — 리뷰 R4차3)**:
- **① n≥100 (유효 — 신규 그룹 방어)**: 신규 C54/C56 정착 그룹은 이번에 **처음 계산**되므로, 어떤 plasma step에서
  부분 결측이면 n<100일 수 있다 → 이걸 잡는다. **이 게이트를 통과하는 그룹에 한해 트림 항상-적용**이 성립하며,
  미달 그룹이 하나라도 있으면 **하드 실패(`RuntimeError`)로 중단** — 소표본을 조용히 트림하지 않는다
  (가드 제거 가정 위반 시 진행 금지). "가드 유지"보다 하드 실패가 게이트 정신에 맞고 구현이 단순
  (가드는 완전 제거, 사전 스캔이 precondition 강제). 현 데이터는 전 그룹 ≥500이라 무발동, 미래 안전망(§9와 일치).
- **② t0 연속성 (이중 방어 — 정상이면 항상 통과)**: window 최소 t0 > 마지막 `C6_1` t0. R1의 복귀-블록 필터가
  갭 가로지름을 **구조적으로 차단**하므로(복귀 블록으로 거른 뒤 last-500 → 갭 이전으로 갈 수 없음) 사실상
  **redundant**. 무해한 belt-and-suspenders로만 유지(실측: 복귀 블록 전 그룹 ≥500).

**silent 실패 방지 하드닝 (리뷰 후속, 2026-07-13)**:
- **정산 무결성 (§3-1 복귀 블록)**: `determine_sample_wafers`가 `len(pre_exp)+len(C6_1)+len(복귀) == len(segment)`를
  검사해 **불일치 시 하드 실패**. C6_1이 **비연속(다중 에피소드)**이면 에피소드 사이 C6_0가 어느 버킷에도 안 들어가
  조용히 사라지므로 이를 잡는다(현 데이터=단일 블록이라 무발동). 라이브 재사용 시 안전망.
- **게이트 정밀화**: 게이트 ①은 그룹 크기가 아니라 **실제 트림 표본 = `min(size, rolling_n)`**으로 검사
  (`sizes.clip(upper=rolling_n)`). `rolling_n < min_trim_n`으로 config가 바뀌어도 "실제 트림 표본이 임계 미만"을
  정확히 잡아 config 결합으로 인한 보장 붕괴를 막는다(현재 500≥100이라 무영향).

## 9. 구현 순서 — 커밋 2단 분리 (리뷰 R7)

config 이관과 4결정을 한 번에 바꾸면 §6-1의 "반영분 외 diff 없음"을 판별할 수 없다. → **2단 커밋**:

- **커밋 ① — config 이관만** (동작 보존): 로드 대상 **5개(`trim_quantile`·`false_alarm_warn_pct`·`cv_warn`·
  `activity_min`·`mag_min`) 상수→config 교체 + 호출-시점 로드/주입 리팩터**(§4-2). → 재생성 산출물
  **diff=0 증명**.
- **커밋 ② — 4결정 + 죽은 코드 제거**: C6_1 제외·C54/56 정착·D_CH5960 제외·조합②(q_low/q_high 등재 포함) +
  **`MIN_TRIM_N`·`MIN_GROUP_N` 가드 제거**(§5 ① n≥100 사전 스캔 게이트 **통과 시에만**; 미달 그룹 있으면 **하드 실패 중단**).
  → **기대 diff만** 발생.

> **⚠️ 가드 제거는 반드시 커밋 ②** (리뷰 R3차1): 커밋 ① 시점엔 C6_1이 아직 있어 C6_1 그룹은
> `n_raw`=33~93 < `MIN_TRIM_N`(100) → **현재 트림 안 됨**. 가드를 커밋 ①에서 제거해 "항상 트림"으로
> 바꾸면 그 그룹들이 갑자기 트림돼 center·σ·UCL/LCL이 바뀜 → **diff≠0**. 이 가드는 C6_1이 빠져 전 그룹
> n≥500이 된 **뒤에야** 진짜 죽은 코드(항상 트림)이므로, 제거를 C6_1 제외와 **같은 커밋(②)**에 묶어야
> no-op이 된다. (§4 표는 config 이관 param과 두 상수 제거를 한 표에 나열하나, **제거 시점은 커밋 ②**임을 여기 못박는다.)
