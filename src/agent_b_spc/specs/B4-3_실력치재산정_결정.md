## 1. 입력·트리거 인터페이스 — 순수 코어 + writer 분리

**결정**
- **계산 코어(순수 함수)**: `최근 N장 값 리스트 + 현행 관리선`을 주입받아 → 재산정안(새 center/UCL/LCL) + 자동/승인 판정을 반환. DB를 모른다.
- **writer**: 자동 확정 케이스만 `control_limits`(새 버전) + `limit_corrections`(이력)에 기록. **commit은 호출자 소유**(tttm_writer 패턴).
- **입력은 버퍼 객체가 아니라 값 리스트(`list[float]`)** 로 받는다.
- 최근 N장 **실제 수급은 B5-1 이월**. B4-3 테스트는 값 주입.

**근거**
- ⓐ **재산정 원천 데이터가 DB에 없음** — 테이블 17개 확인 결과 wafer별 센서 summary 저장 테이블이 없다(`wafer_predictions`는 A의 예측 결과). DB통합형(엔진이 직접 조회)은 읽을 소스가 없어 성립 불가 → 라이브 파이프까지 떠안게 되므로 스코프 초과.
- ⓑ **B 모듈 기존 패턴과 일관** — nelson_engine(순수)/control_limits_loader(읽기)/seed(쓰기), tttm_engine(순수)/tttm_writer(쓰기)와 동일 골격.
- ⓒ **테스트 용이** — 값 주입이라 clamp 경계·자동/승인 분기를 DB 없이 TDD.
- ⓓ 버퍼 객체 대신 값 리스트 → 버퍼 클래스 결합 없음. Nelson 판정버퍼(15장)·TTTM(20장)와 **재산정 500장은 크기·목적이 다른 별개 저장소**라, 판정 버퍼를 재활용하지 않는다.

## 2. 재산정 결과 처리 — 이동량 기준 3구간

**결정** — 새 center가 기존 center에서 이동한 크기에 따라:

| 판정 | 조건 | 코어 행동 |
|---|---|---|
| **변화없음** | 이동 < 0.09σ (dead band) | 새 버전 안 만듦 (스킵) |
| **자동적용** | 0.09σ ≤ 이동 ≤ 0.5σ **그리고** 사이클 누적 ≤ 1.0σ | control_limits 새 버전 + limit_corrections `status=AUTO_APPLIED` |
| **승인대기** | 이동 > 0.5σ **또는** 누적 > 1.0σ | limit_corrections `status=PROPOSED`만, control_limits 미변경 → 승인은 B5-1 |

**근거**
- **자동/승인 경계(1회 0.5σ / 누적 1.0σ)**: 기획서 §4-1 ⓒ "상한 초과 시 **승인 요청으로 전환**" 확정값(reset-cap-sigma: `reset_delta_max_sigma`/`reset_cum_max_sigma_per_cycle`). **clamp(초과분을 잘라 자동 적용)는 채택 안 함** — "초과 시 승인" 원칙을 우회하는 셈이라 헌법 1-1 위반 소지.
- **dead band 0.09σ (= 2×SE)**: 500장 평균은 참값이 안 변해도 표본오차 SE = σ/√500 ≈ 0.045σ만큼 자연히 떨린다. 그 2배(95% 수준)를 넘어야 "노이즈가 아닌 진짜 이동"으로 인정. 미만은 스킵 → 의미 없는 버전 폭증 방지.
- **단위 통일**: 모든 경계가 SE 자(尺)로 통일 — dead band 2×SE, 1회 상한 0.5σ(=11×SE). reset-cap-sigma 근거체계와 정합.

> **헌법 1-1 정합**: 정기+상한이내 → 자동+이력(예외 조항) / 상한초과 → 승인. 승인 없이 실력치 직접 변경 금지 준수.

### 4-b. 사이클 누적 상태 — 이력 조회 + baseline 경계 + 코어 판정

**결정 (H2 signed 순이동 · H3 시작 σ · telescoping — 2026-07-16 자체 리뷰 확정)**
- 누적(A3 1.0σ) = **`|새 center − 리셋 center| / 리셋 σ`** (signed 순이동 + 사이클 시작 σ 기준). 리셋 이후 자동적용 이동들의 signed 합은 **telescoping으로 접혀** 중간값이 상쇄 → "새 center − 리셋 center"만 남으므로 **이력 delta 한 줄씩 합산 불필요**. (H2: 왕복은 상쇄돼 오승인 방지·한 방향 drift만 잡음 / H3: 시작 σ 고정 = reset-cap-sigma A3 결정 정합.)
- **사이클 경계(리셋 지점)** = 기준선이 새로 서는 때: **최초(initial) / Qual / 이상대응(incident) / 승인 적용된 재산정**.
- 코어는 **리셋 기준점(center·σ)을 주입**받아 판정. 리셋 지점 조회는 `correction_history`, 실시간 정밀 리셋은 **B5-1 이월**.

**근거**
- ⓐ 두 테이블에 **pm_count/cycle 컬럼이 없음** → 리셋 지점을 `trigger_type`/`status`로 찾음(TTTM "trigger_type 기준 최신 baseline" 패턴, `(created_at, id)` 경계). 누적은 **telescoping이라 σ 단위 이동량을 이력에 저장할 필요가 없다** — `center_before/after`(기존 컬럼) + 리셋 지점 σ로 계산.
- ⓐ' **`delta_sigma` 컬럼 = 팀 upstream(메인 repo)에 이미 반영됨 → 되돌리지 않고**(헌법 3-2 삭제 금지) **writer가 1회 이동량 기록용으로 활용**하되, 누적 판정은 이 컬럼에 **비의존**(telescoping). *(당초 "%→σ 역산 부정확이라 컬럼 추가 필요"로 판단했으나, H2·H3 telescoping 채택으로 center 기반 계산이 가능해져 누적엔 불요. 이미 반영된 컬럼은 기록용으로 수용 — 스키마 추가 요청 종결.)*
- ⓑ **"승인 적용된 재산정"을 경계에 포함하는 이유**: 누적 초과로 승인받아 큰 이동을 반영했는데 트립미터를 리셋하지 않으면, 다음 periodic마다 누적이 계속 초과로 잡혀 **승인 요청이 폭주**한다. 사람이 "여기가 새 기준"이라 인정한 지점 = 리셋.
- ⓒ **구분**: 누적 트립미터 리셋 ≠ PM 사이클 새 시작. 승인 재산정은 챔버 개방(pm_count↑)이 아니라 **같은 레짐 내 기준점 재확정**. 요란 PM 후 "신규 기준선 수립(R9)"과는 별개.

## 5. KEEP\* 분위수 그룹 (2-track) — 대칭 근사 확정

**결정 (옵션 A — 대칭 근사)**
- **재산정 산식**: 재산정 시기 도래 시 최근 500장에서 q_low/q_high 분위수를 다시 뽑아 **새 UCL/LCL**, center = **trimmed mean**(initial과 동일 산식) 산출. *(UCL/LCL만 분위수 재계산, center는 sigma 그룹과 같은 mean — initial_limits가 분위수 그룹 center도 mean으로 저장하므로 median으로 바꾸면 첫 재산정에서 mean−median만큼 가짜 이동이 뜸. 2026-07-16 spec 작성 중 코드 확인으로 정정.)*
- **이동량·상한·dead band**: σ가 없으므로 **robust σ = (UCL−LCL)/6** 을 σ 대용 "자(尺)"로 대입(q값이 ±3σ 등가라 역산 — robust σ는 관리선 만드는 식이 아니라 **이동량을 σ 단위로 재는 자**). 이 robust σ로 center 이동을 재고, sigma 그룹과 **동일 3구간(변화없음/자동/승인)·동일 배수**(dead band 2×SE, 상한 0.5σ/1.0σ) 적용.
- **비대칭은 대칭 근사** — robust σ 하나로 접어 방향 구분 없이 판정.

**근거**
- ⓐ **TTTM 엔진과 일관** — TTTM도 같은 robust σ 대칭 근사를 택하고 방향별을 후속으로 명시(TTTM spec §3-4 #8). 두 엔진이 같은 자를 써야 유지보수 일관.
- ⓑ **정밀도 부차적** — KEEP\* 분위수는 오탐 감소(±3σ 4.4% → 분위수 0.3%)가 목적이지 상한을 정밀히 재려는 게 아님. 상한은 "크게 튀는 것만 막으면" 되므로 대칭 근사로 충분.
- ⓒ **데모 스코프** — 조합② 자체가 실용 타협.

**후속 (명시적 한계)**
- robust σ를 단일 대칭값으로 접으면 skew 방향 감도가 뒤틀림(긴 꼬리 쪽 과소·반대쪽 과대). 방향별 분리(σ_up=(UCL−center)/3 / σ_down=(center−LCL)/3)는 **후속**으로 미루고 **W7 Scorecard 미탐 관측으로 판단** — 미탐 발생 시 방향별 확장 또는 조합② 롤백(±3σ 회귀) 검토. "이건 근사"임을 정식 spec에 명시적 한계로 기록.

## 6. trigger_type / status 라벨링

**결정 — 두 컬럼의 역할 분리**
- **trigger_type = 재산정 원인**(한 번 정해지면 고정): `initial`(최초 v1) · `periodic`(정기 리캘리) · `incident`(이상 대응 재설정) · `qual`(개방·정비 후 재수립). *(provisional=가한계는 B6-3.)*
- **status = 처리 상태**(시간에 따라 변함, **DB 저장값은 영문** — spec §3-1 M4 정합): `PROPOSED`(대기) → `AUTO_APPLIED`(자동적용) / `APPROVED_APPLIED`(승인적용) / `REJECTED`(반려). *(이하 본문의 한글 표기는 이 영문값의 설명.)*

**상태 흐름**
```
재산정안 생성
├─ 상한 이내(자동) → status=자동적용 ── 바로 반영
└─ 상한 초과(승인) → status=대기 ── 승인 게이트 ──┬─ 승인적용 (반영)
                                               └─ 반려 (폐기·기존 관리선 유지)
```

- **정기 상한초과 승인 케이스** = trigger_type `periodic` **유지**(출발 이유는 불변) + status `승인적용`으로 표시 → **새 trigger_type 값 불필요.**
- **누적(트립미터) 규칙**: `status=자동적용`인 `periodic`만 누적에 합산. 나머지(initial·qual·incident·**승인적용**)는 전부 **리셋 지점** (4-b 사이클 경계와 정합).

**B4-3 스코프**
- B4-3는 재산정안을 `자동적용`(상한 이내) 또는 `대기`(상한 초과)까지만 발행. **대기 → 승인적용/반려 전이는 승인 게이트(LangGraph, B5-1) 몫** — 재산정 코어는 사람 승인을 직접 처리하지 않음.
- status는 기존 `limit_corrections.status` 컬럼 활용, trigger_type 새 값 없음 → **스키마 변경 없음.**
