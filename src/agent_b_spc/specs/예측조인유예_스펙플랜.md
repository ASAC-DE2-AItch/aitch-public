## 1. 문제

B(`spc_consumer`)와 A(`a-pred`)가 같은 `fdc.raw` 를 각자 읽는다. B 는 `fdc.prediction` 도 구독해 wafer_id 로 캐시에 담고, 알람을 만들 때 그 wafer 의 예측을 꺼내 붙인다(= **조인**). 실패하면 중립 스텁(`predicted_c65=0.0` · `shap_top3=[]`)으로 채운다.

**실측 (2026-08-11 · DB 초기화 + 컨슈머 재기동 후 · 시연 속도 `--delay 0.01` · 알람 2,107건)**

```
원인 ① 경합   B 알람이 A 발행보다 먼저      2,095건 (99.4%)
원인 ② 미수신 A 가 먼저 냈는데 조인 실패        4건 ( 0.2%)
   조인 성공                                   8건 ( 0.4%)
```

`poll 기아` 가설은 0.2% 로 기각. **순수한 순서 경합**이다.

| wafer 마지막 row → 발행까지 | p50 | p90 |
| --- | ---: | ---: |
| B 알람 | 0.407s | 0.428s |
| A 예측 | 0.465s | 0.558s |

**차이 58ms.** A 가 늦은 시간은 p50 **57ms** · p90 127ms · max 633ms.

성공한 8건은 여유가 p50 **14.3초** — `lean85.idle_flush_sec=15` 가 발동한 wafer 다. 즉 **idle 경로에서는 성립하고 next-wafer 경로에서 전멸**한다.

### 1-1. 왜 지금 구조로는 못 고치나

두 소비자의 wafer 완성 트리거가 **동일**하다.

```
B  _handle_raw:550   같은 챔버에서 wafer_id 가 바뀌는 순간 → 즉시 _flush   (주석: 최소지연 신호)
A                    같은 트리거로 flush
```

그 뒤 A 만 `모델 추론 → Kafka 발행 → B 수신 → 캐시 저장` 왕복을 더 탄다. B 의 조회가 먼저 끝나므로 **구조적으로 빗나간다.**

#173(A 의 `idle_flush_sec` 15초)은 **무입력(tail) 경로**의 순서만 보장한다. 어느 트리거가 발동하는지는 wafer 도착 간격이 정하고, 시연(`--delay 0.01`)에서는 같은 챔버 간격이 약 0.6초라 **next-wafer 트리거가 항상 이긴다**. 실제 팹(약 25분 간격)에서는 idle 경로가 발동해 #173 이 유효하다. **두 PR 은 서로 다른 경로를 덮으며, 합쳐야 전 구간이 성립한다.**

## 2. 결정

### 결정 1 — 유예 방식 = **발행 유예 큐** (sleep 금지)

`sleep` 은 **원리적으로 불가**하다. B 는 단일 스레드 poll 루프이고 `fdc.prediction` 도 같은 루프로 받는다 — 기다리는 동안 예측을 못 받으므로 **기다림 자체가 해법을 막는다.**

따라서 판정까지 끝낸 결과를 **큐에 넣고 루프를 계속 돌린다.** 다음 poll 반복들에서 캐시를 재조회해 도착 즉시 발행한다.

> 이 방식의 부수 이점: 유예는 **상한**이지 고정 지연이 아니다. 예측이 57ms 만에 오면 57ms 만 늦는다.

**기각안**
- ⓐ *flush 자체를 미룸* — 버퍼를 붙잡으면 같은 챔버 다음 wafer 의 row 가 그 버퍼에 섞인다(`_handle_raw:550` 이 `wafer_id` 변경 시 flush 후 같은 buf 재사용). 별도 보관 구조가 필요해 ⓑ보다 복잡한데 이득이 없다.
- ⓒ *조인 실패를 수용* — AE 배점 0 이면 점수는 무해하나 `predicted_c65`·`shap_top3` 결측이 남는다(§6).

### 결정 2 — 분할 지점 = `_process_wafer` 의 **seam 호출 직전**

`_flush` 는 현재 `_process_wafer`(판정 + seam[조인·채점·발행·적재]) → 버퍼 리셋 → 커밋 순이다.

유예는 **seam 만** 미룬다. 판정(Nelson·TTTM)과 TTTM 적재는 그대로 즉시 수행한다 — 그쪽은 예측과 무관하고, 미루면 TTTM rolling 이 어긋난다.

```
_process_wafer:
    Nelson·TTTM 판정 · TTTM 적재            ← 즉시 (무변경)
    ┌ 예측 캐시 조회
    │   hit  → seam 호출 (기존 경로 — 지연 0)
    └   miss → _pending_join 에 적재 후 return   ← 신규
```

seam 은 조인·채점·발행·`spc_violations` 적재를 한 덩어리로 하므로, **알람과 DB 행이 함께 미뤄져** 둘이 어긋나지 않는다.

### 결정 3 — 커밋 상호작용 = **기존 홀드 패턴 재사용**

발행 전에 커밋하면 크래시 시 **알람이 조용히 유실**된다. B7-1 이 이미 같은 문제를 `_pending_failed`(실패 wafer 의 first offset 을 홀드해 커밋 상한을 잡음, D16)로 풀었다.

같은 형태로 `_pending_join` 항목이 그 챔버의 `first_msg` 를 **홀드**하고, 발행 완료 시 해제한다. 유예가 1초 미만이므로 홀드는 무시할 수준이다.

> ⚠️ 홀드를 안 걸면 "커밋은 됐는데 알람은 안 나간" 구간이 생긴다 — 헌법 7장의 *"영속화 consumer 를 자동 커밋으로 운용"* 과 같은 형태의 무기록 유실이다.

### 결정 4 — 상한 = `prediction_join_grace_ms: 800` · 드레인은 매 poll

실측 max 633ms 에 여유를 둔 값이다. p90 이 127ms 라 **평균 체감 지연은 약 57ms**이고, 800ms 는 a-pred 가 죽었을 때의 천장으로만 작동한다.

- 드레인은 **매 poll 반복**(별도 캐던스 없음) — 예측 도착 즉시 나가게.
- 상한 초과 시 **현행 동작 그대로**(중립 스텁으로 발행). 알람을 버리지 않는다.
- 큐 상한 `prediction_join_pending_max: 500` — 초과 시 가장 오래된 것부터 즉시 발행(메모리 가드).

### 결정 5 — 관측 4종 (조용한 게이트 금지)

헌법 7장 *"조용한 상태 게이트를 카운터만 두고 노출 없이 운용 금지"*.

| 카운터 | 의미 |
| --- | --- |
| `join_grace_enqueued` | 유예로 들어간 wafer 수 |
| `join_grace_resolved` | 유예 중 예측이 도착해 조인 성공 |
| `join_grace_expired` | 상한 초과 → 스텁 발행 |
| `join_grace_wait_ms` | 해소까지 걸린 시간(p50·p90 로그) |

기존 `예측 조인 N건: hit/miss` 로그(500건마다)에 **유예 해소분을 hit 으로 반영**한다. 그리고 `join_grace_expired` 가 누적되면 **N건마다 WARNING** — 유예로도 못 잡는 상황(a-pred 정지 등)이 조용히 흐르지 않게.

## 3. 설계

### 3-1. 자료구조

```python
# chamber → deque[PendingJoin]
#   PendingJoin = (wafer_id, chamber_id, ts, violations, tttm_obj, recipe_id,
#                  first_msg, deadline_monotonic)
self._pending_join: dict[str, deque] = defaultdict(deque)
```

챔버별 deque 인 이유: 같은 챔버 안에서는 **wafer 순서를 유지**해 발행하기 위해서다(§5 열린 항목 1).

### 3-2. 배선 지점 3곳

| 위치 | 변경 |
| --- | --- |
| `_process_wafer` seam 호출부 | 캐시 miss 면 seam 대신 `_pending_join` 적재 |
| `run()` poll 루프 | 매 반복 `_drain_pending_join()` 호출 (`_maybe_purge`·`_flush_pm_log` 옆) |
| `_commit` 의 min un-flushed 계산 | `_pending_join` 의 `first_msg` 도 홀드 대상에 포함 |

### 3-3. 드레인 의사코드

```python
def _drain_pending_join(self) -> None:
    """유예 큐 소진 — 예측 도착 or 상한 초과 시 발행. 예외 격리(루프 못 죽임)."""
    now = self.clock()
    for ch in list(self._pending_join):
        q = self._pending_join[ch]
        while q:                                  # 챔버 내 순서 유지 — 앞이 안 풀리면 멈춘다
            item = q[0]
            hit = self.prediction_cache.get(item.wafer_id) is not None
            if not hit and now < item.deadline:
                break                             # 아직 기다린다(뒤도 같이 대기 = 순서 보존)
            q.popleft()
            self.stats["join_grace_resolved" if hit else "join_grace_expired"] += 1
            try:
                self._emit(item)                  # seam 호출 (조인·채점·발행·적재)
            except Exception:
                logger.exception("유예 발행 실패 — wafer=%s", item.wafer_id)
                self._pending_failed.setdefault(ch, item.first_msg)   # D16 회수 경로 재사용
        if not q:
            del self._pending_join[ch]
```

`break` 로 **앞 항목이 안 풀리면 뒤도 대기**시킨다 — 챔버 내 발행 순서를 wafer 순서와 일치시키기 위해서다. 상한이 800ms 라 지연 누적은 유한하다.

### 3-4. 종료 경로

`run()` 의 `finally: _flush_all()` 뒤에 **`_drain_pending_join(force=True)`** 를 붙인다. 강제 드레인은 상한을 무시하고 전부 발행한다 — 안 그러면 종료 시 유예 중인 알람이 사라진다.

## 5. 열린 항목 — **전건 확인 완료 (2026-08-11)**

### ✅ 1. `alert_id` SEQ — 무영향. 채번 시점 변경 없음

`ALERT-<YYYYMMDD>-<CHAMBER>-<SEQ>` 의 SEQ 는 `spc_violations` 의 **(날짜, 챔버) 범위 max+1** 이다 (`publisher.next_alert_id`). **챔버별로 독립**이라 챔버 간 순서 개념이 없고, 챔버 **내부** 순서는 §3-3 의 `break` 가 보존하므로 SEQ 는 wafer 순서와 계속 단조다.

채번은 발행 시점(seam 안)에 그대로 둔다 — 유예는 단일 컨슈머 안의 순차 발행이라 `next_alert_id` docstring 이 경고하는 **다중 컨슈머 경합을 새로 만들지 않는다.**

### ✅ 2. `is_qual` — 유예 대상 자체가 아님

`alert_seam.py:144` 가 `is_qual` wafer 를 **조인 전에** skip 한다(적재·발행·채점 전부). 예측을 쓰지 않으므로 유예 큐에 들어갈 일이 없고, `session_first_msg` 홀드(§3-1-3)와 겹칠 여지도 없다.

커밋 홀드는 이미 3종(ⓐ 버퍼 미flush · ⓑ `_pending_failed` D16 · ⓒ qual 세션)을 min 으로 합치므로, **ⓓ `_pending_join` 을 같은 방식으로 추가**하기만 하면 된다(결정 3).

### ✅ 3. B9 crazy — 같은 seam. 배선 불필요, 단 **선행 조건 있음**

`alert_seam.py:150` 의 `verdict = is_crazy(pred, ...)` 가 조인된 `pred` 를 받는다. seam 을 통째로 미루면 B9 도 올바른 예측값으로 판정된다.

> ⚠️ **부수 효과** — 지금은 조인 실패로 `pred` 가 스텁이라 B9 가 거의 안 걸린다(라이브 2건 / 2,112). 유예로 조인이 살아나면 **AE 포화가 그대로 반영**돼 B9 가 실측 비율(e4 57.1% · seg1 재학습 40.3%)로 발동한다. 즉 **이 PR 은 B9 발동률을 2건 → 수백 건으로 올린다.**

`is_crazy` 의 anomaly arm 컷은 `anomaly_score_multiplier(3.0) × ae_anomaly_threshold(0.2) = 0.6` 이고, 포화가 **정확히 1.0** 이라 **컷 조정으로는 못 피한다**(1.0 미만 컷은 전부 발동, 1.0 초과 컷은 영구 미발동 = 잠금과 동일).

## 5-1. B9 를 잠그지 않기로 할 경우 — 무슨 일이 생기나

세 경로를 각각 확인했다. **물리 조치로는 안 가지만, 화면과 비용에는 그대로 나온다.**

| 경로 | 결과 | 근거 |
| --- | --- | --- |
| **RTD 자동 챔버 정지** | ✅ **안 감** | `chamber_inhibit._is_ae_only()` 가 anomaly-only B9 를 명시 제외하고, `rtd.exclude_ae_arm: true` 가 현 설정. `min_violation_sensors` 게이트도 앞단에 있다 |
| **C Agent(LLM) 호출** | ✅ 대체로 안 감 (**AE 배점 0 전제**) | crazy 알람은 B9 마커 **단독** 알람이라 점수 = e1 0 + e3 20 → **게이트 31 미달**. AE 배점이 살아 있으면 +30 = 50 이라 통과 |
| **Incident 그룹핑·wafer HOLD** | 🔴 **간다** | `incident_grouper` 는 *"context_score < B7 도 그룹핑·기록은 한다 (agent 트리거만 downstream gating)"*(주석 §13). 게이트와 무관하게 crazy 알람마다 Incident 에 편입되고 wafer 처분 경로가 열린다 |

즉 잠그지 않으면 **wafer 의 약 40%가 crazy 로 기록되고 HOLD 경로에 오릅니다.** 물리적 정지는 아니고 되돌릴 수 있는 상태지만(HOLD 는 인터락 원위치), 시연 화면과 DB 에는 그대로 남습니다.

**그래서 선택지는 둘이다.**

| 안 | 내용 | 평가 |
| --- | --- | --- |
| **ⓐ B9 anomaly arm 잠금** | `spc.crazy_wafer` 에 스위치 신설 → `is_crazy` 의 anomaly arm 게이팅. predicted arm 은 유지 | Qual `use_ae_axis: false`·RTD `exclude_ae_arm: true` 와 **같은 논리**의 세 번째 적용. AE 포화 해소 시 되돌림 |
| **ⓑ 유예를 끈 채로 병합** | `prediction_join_grace_ms: 0` (킬 스위치, §4)으로 머지하고 B9 결론 후 켬 | 코드는 미리 들어가고 활성화만 미룬다. **잠그지 않기로 하면 이쪽이 강제된다** |

**따라서 "B9 를 잠그지 않는다"는 결정은 곧 "유예를 켜지 않는다"와 같다.** 둘은 한 스위치로 묶여 있다 — 조인을 고치는 것이 곧 B9 를 실제 비율로 깨우는 것이기 때문이다.

킬 스위치가 스펙에 이미 있으므로(§4 `prediction_join_grace_ms: 0`) **구현은 어느 쪽 결정이든 진행할 수 있다.** 활성화 시점만 B9 결정에 종속된다.

## 6. 범위 밖 (별건)

- **결측 시 안전측 낙하** — 유예로도 못 받으면 여전히 스텁(`predicted_c65=0.0`)이 나가고, C 의 `predicted is None → HOLD` fail-safe 를 지나쳐 **RELEASE 오권고**가 된다. 이는 계약 §3 의 `predicted_c65` 필수(non-Optional) 때문이며 **C·PM 합의 사안**이다(`publisher.py:451` 의 `(Q1 — C 통보 후 조정)` 미해결분). 유예는 결측 **빈도**를 줄이고, 계약 수정은 결측 **결과**를 안전측으로 만든다 — 둘 다 필요하다.
- **AE 배점** — 이 건과 직교한다. 배점은 B 내부 점수 계산에만 걸리고, 조인 결측은 알람 페이로드의 원값에서 난다.
