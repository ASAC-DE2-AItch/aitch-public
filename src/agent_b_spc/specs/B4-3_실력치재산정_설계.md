## 1. 목적 & 범위

정기 리캘리 시점에 **최근 N장 값 + 현행 관리선 + 리셋 기준점**을 받아 새 관리선을 재산정하고, 이동량에 따라 **변화없음/자동적용/승인대기**를 판정한다. **자동**은 control_limits 새 버전 + limit_corrections 이력에 반영하고, **승인대기**는 limit_corrections에 `PROPOSED` 이력만 남긴다(control_limits 불변 — M6). 입력은 값·기준점 주입이라 라이브·배치 무관하게 재사용 — D0/Kafka 독립.

### 범위 경계 (In / Out)

| In (이 설계) | Out (이월) |
|---|---|
| 그룹 재산정 산식(sigma mean±3σ / 분위수) — initial과 공유 | 최근 N장 실시간 수급(라이브 버퍼/적재) → **B5-1** |
| robust σ 이동량 판정 + dead band + 상한(1회 활성σ / 누적 시작σ) | **호출 게이팅**(무이상일 때만 호출 — §3-6) → **B5-1** |
| 3구간 판정(변화없음/자동/승인) + trigger_type/status | fdc.correction 구독 → 한계 즉시 갱신 → **B5-1** |
| 누적 telescoping + 리셋 지점 조회 + 자동 케이스 writer | 섀도 평가(승인 케이스 안전성) → **B5-1** |
| 분위수 KEEP\* robust σ 대칭 근사 | 승인대기→승인적용/반려 전이(승인 게이트) → **오케스트레이터/B5-1** |

> B4-3 = "재산정이 *호출됐을 때* 무엇을 계산·판정하나". B5-1 = "*언제·어떻게 호출하나*(무이상 게이팅 포함)".

> **산식 공유 (헌법 정신 — 산식 통일)**: 현 `compute_limits`의 그룹별 로직(트림→mean/std→±kσ, 트림 전 values에서 q_low/q_high 분위수)을 순수 함수 `compute_group_limits(values, cfg)`로 **추출**한다. 🔴 **반환은 QA 필드까지 포함해야 한다(리뷰 H3)** — `sample_min/max`는 **트림 후 배열**에서만 나오고 그 둘이 `wide_limits` 플래그를 결정하며, `qa_flags`는 CSV·`seed_control_limits`를 거쳐 control_limits까지 전파된다. 반환에서 빠지면 호출자가 트림을 재실행해야 해 산식 통일이 무너지거나 qa_flags가 소실돼 **"회귀 0"이 성립하지 않는다**. `initial_limits`는 groupby 루프에서 이를 호출하도록 리팩터, `recalc_engine`도 같은 함수를 호출 → **initial과 recalc가 동일 산식 보장**(리팩터는 회귀 0 — 기존 initial 테스트로 검증).
> **resolution 산출·로드 (리뷰 M-B + 흐름 갭 보완)**: ⓐ **산출** — `compute_group_limits`에 그룹별 resolution(정렬 unique의 최소 인접 간격) 계산 추가. ⚠️ **`len(uniq) ≤ 1`이면 `0.0` early return**(상수·극소표본 그룹에서 `np.diff`가 빈 배열 → `np.min` 예외로 산출 파이프라인 정지 방지 — 리뷰). ⓑ **저장** — `initial_limits`가 `initial_limits_v1_meta.json`(또는 CSV)에 그룹별 저장. ⓒ **로드** — `initial_limits.load_resolutions(meta_path) -> {4-tuple: resolution}` 헬퍼(신규)로 읽어 재산정 호출자(테스트=직접 주입 / 라이브=B5-1)가 `recompute_group`의 resolution 인자로 주입. 🔴 **키는 chamber를 뺀 `(recipe_id, step, sensor_window, sensor_id)` 4-tuple** (리뷰 H1) — `initial_limits` 산출물의 chamber는 원 챔버 `C24_0` 하나뿐인데 라이브는 `SIM_CH_*`라, chamber를 키에 넣으면 **전 그룹 조회 miss → res_σ=0 고정으로 기능이 조용히 죽는다**. 챔버 오프셋은 밴드 **평행이동**이라 값 간격(diff)을 바꾸지 않으므로 **분해능은 챔버 무관**이 근거. 조회는 `group_key[1:]`. meta(JSON)는 튜플 키 불가 → `"C6_0|4|settled|C11"` 구분자 조인 규약. (`correction_history`는 DB 소스만 — resolution은 meta 소스라 로드 경로가 별개.) **결정 4-a 준수 — control_limits/DB 스키마 무변경**(물리 상수라 1회 고정). ⚠️ 현재 `initial_limits`는 산출·로드 둘 다 없음 → **B4-3 구현 항목**(산출물 재생성, 관리선 값 불변 회귀 확인).

## 3. 확정 설계 결정 (구현 관점)

### 3-1. 입력·출력 계약 — 순수 코어 (결정 1·2)

```
recompute_group(
    group_key: tuple,           # (chamber_id, recipe_id, step, sensor_window, sensor_id) — writer 매핑·correction_id 생성용 (리뷰 M-C)
    values: list[float],        # 최근 N장 (주입 — 라이브 수급은 B5-1). NaN/None은 코어가 필터
    current: dict,              # 현행(활성) 관리선: {center, sigma, ucl, lcl, method, limit_version}
    reset_ref: dict,            # 사이클 시작 기준점: {center, sigma_ref} (correction_history 조회 결과 주입 — H3)
    resolution: float,          # 그룹 분해능 (baseline meta 주입 — 결정 4-a)
    cfg: RecalcConfig,          # §6
) -> RecalcProposal
```

**RecalcProposal** (writer가 소비):

| 필드 | 값 |
|---|---|
| `group_key` | 그룹 키 (writer가 컬럼 매핑·correction_id 생성에 사용 — 리뷰 M-C) |
| `decision` | `no_change` / `auto_applied` / `needs_approval` |
| `new_center` `new_ucl` `new_lcl` `new_sigma` | 재산정 관리선 (no_change면 None). ⚠️ **`new_sigma` 필수** — control_limits `sigma`가 **NOT NULL**이라 없으면 INSERT 크래시(리뷰 H2) |
| `n_used` | 트림 후 유효표본 수 → limit_corrections `calc_window_n` (리뷰 H2) |
| `delta_sigma` | **1회 이동량**(σ 단위, 활성 sigma_ref 기준) — writer가 limit_corrections에 **기록**(감사·표시용, 누적엔 비사용 §3-4) |
| `method` | `sigma` / `quantile` (current 승계) |
| `trigger_type` | `periodic` (고정 — 결정 6) |
| `status` | `AUTO_APPLIED` / `PROPOSED` — no_change면 없음 |
| `reason` | no_change 사유(`dead_band`/`small_sample`/`degenerate`/`resolution_bound`) |

> **status 값은 영문(DB 저장값, 리뷰 M4)**: `PROPOSED`(대기) · `AUTO_APPLIED`(자동적용) · `APPROVED_APPLIED`(승인적용) · `REJECTED`(반려). 기존 `limit_corrections.status DEFAULT 'PROPOSED'`와 정합. 한글(대기/자동적용…)은 문서 설명용.

### 3-2. 자(尺) = robust σ (결정 5 — 대칭 근사)

- **sigma 그룹**: `sigma_ref = current.sigma`. UCL/LCL = new center ± k·σ.
- **quantile 그룹(KEEP\*)**: `sigma_ref = (current.ucl − current.lcl) / (2·k_sigma)`. center = `new.center`(= compute_group_limits의 **trimmed mean** — sigma 그룹과 동일 산식), UCL/LCL = 새 q_lcl/q_ucl. **robust σ는 이동량을 σ 단위로 재는 자일 뿐, 관리선 산식이 아님.** 비대칭은 대칭 근사(방향별은 후속·W7 관측).
  - ⚠️ **6 하드코딩 금지 (리뷰 L8)**: `(ucl−lcl)/(2·k_sigma)`로 계산. `k_sigma`가 config 3.0이라 현재 분모가 6이지만, **`2·k_sigma`로 두어 k 변경에 자동 추종**(헌법 6-1 — TTTM `sigma_ref`와 동일 패턴).
  - ⚠️ **center=mean 통일 (median 아님)**: initial_limits가 분위수 그룹도 center=trimmed mean으로 저장하므로, median으로 바꾸면 initial과 정의가 달라져 **첫 재산정에서 (mean−median)만큼 가짜 이동**. initial과 동일 산식(mean)이 이동량 정합의 전제.
- **정합 가드(#12)**: `q_high`의 Φ⁻¹ ≈ `k_sigma` 를 로드 시 assert (TTTM `_check_q_k`와 동일 — `statistics.NormalDist().inv_cdf`). q값과 k가 어긋나면 σ_ref가 조용히 틀어짐.
- **공유 헬퍼 (중복 방지 — 리뷰 H4)**: sigma/robust σ 계산은 **`recalc_engine.sigma_ref_of(limit_row, k_sigma)` free function 한 곳**에 둔다(소유 모듈 확정). `recompute_group`(current)·`correction_history`(리셋 지점) 모두 이걸 import해 호출 — `reset_ref.sigma_ref`도 이 헬퍼 산출값. ⚠️ `tttm_engine.sigma_ref`(인스턴스 메서드)는 **건드리지 않는다 — 명시적 범위 밖**(위임 리팩터는 회귀 위험 > 이득).
- `sigma_ref ≤ EPS`(zero_sigma·밴드 붕괴) → `no_change(degenerate)` skip.

### 3-3. 3구간 판정 — 전부 σ 단위, 누적은 telescoping (결정 2·4 / 리뷰 H2·H3)

먼저 **NaN/None 필터(리뷰 L11)** → `n_used = len(유효값)`. **가드를 나눗셈보다 먼저 둔다**(리뷰 H-A — `tttm_engine.py:177` 관례. 계산 뒤에 가드를 두면 `sigma_ref=0.0`에서 `ZeroDivisionError`):

```
new = compute_group_limits(values_filtered, cfg)                 # center=trimmed mean, q_lcl/q_ucl

# ── 가드 (모든 나눗셈 前 — 리뷰 H-A) ──────────────────
if n_used < cfg.min_group_n:            return no_change(small_sample)     # 결정 4-c 방어
if sigma_ref ≤ EPS:                     return no_change(degenerate)       # current σ 퇴화(zero_sigma·밴드붕괴)
if reset_ref is None:                   return needs_approval(PROPOSED)    # 리셋 기준점 부재(M7) → 보수적 승인 (None.sigma_ref 방지)
if reset_ref.sigma_ref ≤ EPS:          return needs_approval(PROPOSED)    # 리셋 σ 퇴화 → 보수적 승인(§8)

# ── σ 단위 환산 (가드 통과 후 — 물리 단위 혼용 금지) ──
delta1_σ   = |new.center − current.center| / sigma_ref            # 1회 이동량 (활성 σ 기준 — A2)
cum_σ      = |new.center − reset_ref.center| / reset_ref.sigma_ref  # 누적 순이동 (시작 σ 기준 — A3, telescoping)
SE_σ       = 1 / √n_used                                          # 표본오차. n_used = 트림 후 유효표본 (리뷰 M6)
res_σ      = resolution / sigma_ref                               # 분해능(σ). resolution None/≤0 → res_σ=0(항 skip)
dead_band  = max(cfg.deadband_k_se · SE_σ, res_σ)                # 결정 2: k=2 → 2/√500≈0.09σ
cap_1      = max(cfg.reset_delta_max_sigma, res_σ)               # 0.5σ, 하한 분해능
cap_cum    = cfg.reset_cum_max_sigma_per_cycle                   # 1.0σ

# ── 자동 불가 그룹 (리뷰 H5) ─────────────────────────
if res_σ ≥ cfg.reset_delta_max_sigma:   return no_change(resolution_bound) # 분해능 ≥ 1회 상한 → 미세 조정이 물리적으로 불가

# ── 3구간 판정 ───────────────────────────────────────
if delta1_σ < dead_band:                return no_change(dead_band)        # 결정 2 변화없음
if delta1_σ > cap_1 or cum_σ > cap_cum: return needs_approval(PROPOSED)   # 결정 2 승인
else:                                   return auto_applied(AUTO_APPLIED)
```

- **H2 signed 순이동**: `cum_σ`는 `new.center − reset_ref.center`의 **크기**(왕복은 상쇄 → 순이동만). 정상 진동은 누적에 안 쌓여 오승인 방지, 한 방향 drift만 잡음. **1회는 방향 무관 폭(`delta1_σ`)**, 누적은 순이동 — 역할 분리.
- **H3 telescoping**: 리셋 이후 자동적용들의 signed 이동 합은 중간이 상쇄돼 **`현재/새 center − reset center`**로 접힘 → 이력 delta 합산 불요, `reset_ref`만 있으면 계산. σ 기준은 **시작 σ**(`reset_ref.sigma_ref`, quantile이면 리셋 지점 robust σ) — reset-cap-sigma 결정(A3=사이클 시작 σ 고정) 정합.

> **resolution 가드 (리뷰 L3 — fallback 상수 기각)**: `res_σ=0`이 되어도 `dead_band = max(2×SE_σ, res_σ)`라 **2×SE_σ(≈0.09σ)가 하한 유지** → dead_band>0. "resolution 누락 → 글리치 스팸"은 **구조적 불가**, `0.01` 같은 fallback은 **불요**(매직넘버 회피 6-1). None/≤0 **타입 방어만**. (resolution=0 상수 그룹은 zero_sigma→EXCLUDE + `sigma_ref≤EPS` skip으로 이중 차단.)

> **자(尺) 관련 명시 (리뷰 L-C·L-D)**: dead_band의 `2×SE`는 current.center를 확정 기준값으로 본 **휴리스틱 억제 문턱**이다(두 표본평균 차의 엄밀 SE는 √2×SE라 실효 커버리지 ~84%지만, 오탐↑(무의미 버전 증식) 방향이라 안전 하한 침해 아님). 1회=활성 σ·누적=시작 σ로 자를 나눈 건 **의도된 설계**(트립미터 vs 속도계) — 사이클 후반 밴드가 크게 좁아지면 1회 캡이 물리적으로 더 민감해질 수 있으나 이 역시 보수(승인↑) 방향이라 안전 위배 없음.

### 3-4. 리셋 지점 조회 & 사이클 경계 (결정 4-b / telescoping)

`correction_history.reset_ref(conn, group_key) -> {center, sigma_ref}` — **2-소스 병합 (리뷰 M-A)**:
- ⚠️ `initial`은 limit_corrections에 **존재하지 않는다**(seed_control_limits는 control_limits에만 시딩, DDL trigger_type 도메인도 `incident/qual/periodic`뿐). 따라서 리셋 지점을 limit_corrections 단독으로 찾으면 periodic-only 사이클에서 빈 결과 → 누적 오판(헌법 1-1 경계 리스크). 2-소스로:
  - **ⓐ 기저** = control_limits의 `trigger_type='initial'`·`limit_version='v1'` 행 center·σ. 재산정 후 이 행은 `is_active=false`이므로 **active 필터 금지**(limit_version으로 조회).
    - 🔴 **`control_limits_loader.load()` 재사용 금지 (리뷰)**: 그 로더는 `WHERE is_active = true` **고정**이라, 재산정이 한 번이라도 돌면 v1 기저(is_active=false)를 **못 찾아 reset_ref 탐색이 통째로 실패**한다. `correction_history`는 **전용 쿼리**를 쓴다 — 조건은 `group_key + limit_version='v1' + trigger_type='initial'`뿐, **`is_active` 조건은 아예 넣지 않는다**(불변식).
  - **ⓑ 덮어쓰기** = limit_corrections에서 `trigger_type ∈ {qual, incident}` **또는** `status='APPROVED_APPLIED'`인 최신 행이 있으면, 그 `limit_version_after`의 control_limits center·σ로 기저를 대체.
- **정렬·경계(리뷰 L1)**: ⓑ 조회는 `(created_at DESC, id DESC)` 정렬 — `id`(BIGSERIAL)를 tie-breaker로(동일 created_at·승인 out-of-order 순서 모호 제거). quantile 그룹이면 robust σ=(ucl−lcl)/(2·k) 계산.
- **periodic-only 사이클**(재산정 이력은 있으나 리셋-타입 없음) → ⓑ 없음 → **ⓐ 기저(v1) 사용**. 첫 사이클도 동일.
- **delta 합산 안 함(telescoping)**: 누적은 `recompute_group`이 `new − reset_ref.center`로 계산 → 헬퍼는 **기준점만** 제공. `delta_sigma` 컬럼(§4)은 감사·표시 기록이지 누적 입력이 아니다.

> 실시간 pm_count 정밀 리셋은 B5-1 이월. 코어·헬퍼는 이력 기반(리셋 지점) telescoping으로 충족.

### 3-5. trigger_type / status (결정 6)

- `trigger_type='periodic'` 고정(정기 리캘리 출발). 상한 초과 승인 케이스도 periodic 유지 — 승인 여부는 status로.
- `status`(영문): 코어는 `AUTO_APPLIED`(상한 이내) 또는 `PROPOSED`(초과)만 발행. **PROPOSED→APPROVED_APPLIED/REJECTED 전이는 승인 게이트(B5-1)** — 코어·writer는 사람 승인 미처리.
- 스키마 변경 없음(trigger_type 새 값 X, status 기존 컬럼 값 확장).

### 3-6. 무이상 게이팅 — 호출 전제 (리뷰 H1, 헌법 1-1)

- 헌법 1-1 자동 적용 예외 = ⓐ상한이내 ⓑ이력 **ⓒ무이상 상태** 3조건. 코어는 ⓐⓑ를 보장하나 **ⓒ(무이상)는 값만으로 판별 불가.**
- **불변식**: `recompute_group`은 **무이상 상태 전제로만 호출**된다. **Incident 진행 중·가한계(Phase 0~1) 챔버·그룹에서의 호출 금지는 상류(B5-1) 책임**(결정 3 — "트리거=주기+무이상", 사이클_정의 R2). 이상 상황 재산정을 자동적용하면 진짜 이상을 정상으로 흡수 → 헌법 1-1 위배.
- 코어는 방어적으로 이 전제를 **문서화만** 하고 게이팅 로직은 두지 않는다(값만 받으므로). 게이팅 배선은 §9 이월.

## 4. limit_corrections 매핑 (writer)

아래 표는 **`apply_auto`(자동 케이스)** 매핑 — 승인대기는 `record_proposed`(이 절 하단). **진입 가드(리뷰)**: `apply_auto`는 `proposal.decision == 'auto_applied'`가 아니면 **아무것도 쓰지 않고 반환 + 로그**한다(호출자만 믿지 않는 이중 방어). `no_change`의 `new_* = None`이 흘러들면 control_limits는 `center NOT NULL` 위반으로 터지고, **limit_corrections는 nullable이라 NULL 이력이 조용히 남는다**(후자가 더 위험 — 감지 안 됨).

**기존 컬럼만 사용**(`delta_sigma` 포함 — 팀 upstream 반영 완료, 아래):

| 컬럼 | 값 |
|---|---|
| `correction_id` | **`LIM-<YYYYMMDD>-<CHAMBER>-<SEQ>`** (헌법 6-4 포맷, NOT NULL UNIQUE·DEFAULT 없음 — 리뷰 H-B). **채번 = `COALESCE(MAX(SEQ), 0) + 1`** (같은 `날짜+chamber_id` 범위). ⚠️ **NULL 가드 필수** — 당일 첫 건은 행이 없어 `MAX`가 NULL → `None+1` TypeError로 **매일 첫 재산정이 죽는다**(일상 케이스). ⚠️ **`FOR UPDATE`만으론 부족** — 행이 없으면 잠글 대상이 없어 동시 첫 건이 둘 다 SEQ=1을 채번 → **UNIQUE 위반 시 +1 재시도(최대 N회)를 주 안전망으로** 둔다(락은 보조). 파이썬 `count+1`·메모리 카운터 **금지** |
| `chamber_id`·`recipe_id`·`step`·`sensor_window`·`sensor_id` | group_key |
| `limit_version_before` / `limit_version_after` | current.limit_version / 신규 버전(§5) |
| `center_before` / `center_after` · `ucl_after` · `lcl_after` | current.center / new_* |
| `delta_pct` | 표시용 %. `center_before≈0`(0중심 잔차 센서)이면 **NULL**(0 나눗셈 가드 — 리뷰 L10) |
| `delta_sigma` | **1회 이동량(σ)** = `delta1_σ` 기록 — 감사·표시용. **누적 판정엔 비사용**(§3-4 telescoping) |
| `trigger_type` | `periodic` |
| `calc_window_n` | 트림 후 실사용 표본 수(n_used) |
| `effective_from` | 자동 적용 시각(=control_limits 신규 행의 effective_from과 동일 값) — 리뷰 L6. NULL로 두면 계약 §2-1의 `fdc.correction.effective_from`을 B5-1이 되살릴 소스가 없음 |
| `status` | `AUTO_APPLIED` (자동) / `PROPOSED` (승인대기 — `record_proposed`가 기록, 아래) |

> **승인대기도 이력에 남긴다 (리뷰 M6 — 결정 문서 §2와 정합)**: `record_proposed(conn, proposal)`가 **limit_corrections에 `status=PROPOSED` 행만** INSERT한다(**control_limits는 미변경** — 관리선은 승인 후에야 바뀜). 근거: ⓐ 헌법 1-1 ⓑ가 요구하는 **감사 추적**은 승인 요청에도 적용되고, ⓑ B5-1 승인 게이트가 "무엇을 승인할지" 읽을 **DB 소스**가 필요하다(안 남기면 재산정안이 프로세스 메모리에만 존재하다 사라짐). `center_after`·`ucl/lcl_after`엔 제안값을 채우되 control_limits는 그대로 둔다. PROPOSED→APPROVED_APPLIED/REJECTED 전이는 여전히 **B5-1**.

> **`delta_sigma` 컬럼 = 팀 upstream 반영 완료(수용)**. PM이 메인 repo `db/init.sql`에 이미 ALTER ADD → **되돌리지 않는다**(헌법 3-2 — 컬럼 삭제 금지, 이미 머지). 우리 로컬 B파트 repo는 upstream sync 시 컬럼 유입. writer가 **1회 이동량을 기록**해 컬럼을 활용하되, **누적 계산은 telescoping(center 기반)이라 이 컬럼에 의존하지 않음** — 둘은 독립.

**① 현행 행 조회 (신설 — 리뷰 H2)**: `apply_auto`는 먼저 group_key의 현행(is_active) control_limits 행을 **`SELECT … FOR UPDATE`로 잠그며 읽어** `limit_version_before`·`center_before`·`method`·`q_low`/`q_high`·`k_sigma`를 취득한다. 이 값들은 **proposal에 없다**(loader가 6키만 반환 → q_low/q_high·k_sigma는 애초에 파이프라인에 부재). 어차피 다음 단계에서 이 행을 UPDATE해야 하므로 **잠그면서 읽으면 동시성 안전까지 확보**. 조회 결과가 없으면 쓰기 없이 반환+로그.

control_limits 새 버전 — **쓰기 순서 불변식(리뷰 L2)**: **② current 행 `is_active=false` UPDATE 먼저 실행 완료 → ③ 신규 행 `is_active=true` INSERT**(`sigma`=proposal.new_sigma, quantile이면 ①에서 읽은 q_low/q_high 승계). `idx_control_limits_active_one`(partial unique `WHERE is_active` + immediate check)라 INSERT를 먼저 하면 **그 문장 시점 active 2개로 제약 위반**(단일 트랜잭션 statement 순서 — 동시성 race 아님). 신규 행 `trigger_type='periodic'`·`method` 승계·(quantile이면 q_low/q_high 유지).

## 5. 버전 발급 (헌법 4-1)

- 재산정은 **새 limit_version** 부여, 기존 행 보존(덮어쓰기 금지).
- **그룹별 증가 확정(리뷰 L9)**: `v1→v2…`를 **그룹별 독립**으로 매김(전역 단조는 한 그룹 재산정에 전역 버전 점프라 부적절). control_limits `UNIQUE(group, limit_version)`이 그룹별을 보장. Nelson/TTTM의 `limit_version` flush 신호도 그룹별 point 기준이라 정합.
- 🔴 **채번은 숫자 캐스팅 (리뷰 M2)**: `MAX(CAST(SUBSTRING(limit_version FROM 2) AS INT)) + 1` → `'v' || n`. **문자열 MAX 금지** — `'v9' > 'v10'`이라 v10부터 버전이 역전돼 UNIQUE 충돌 또는 후퇴가 난다. 비정형 버전 문자열은 방어(정규식 미스매치 시 실패+로그).
- writer는 **commit 안 함**(tttm_writer 패턴) — 트랜잭션 경계 호출자(테스트=rollback / 라이브=commit).

## 6. Config (헌법 6-1)

**`RecalcConfig` (리뷰 M5 + M1 정정)** — 🔴 **`LimitConfig`를 합성으로 품는다**: `RecalcConfig(limit: LimitConfig, deadband_k_se, reset_delta_max_sigma, reset_cum_max_sigma_per_cycle)`. 산식 호출은 **`compute_group_limits(values, cfg.limit)`**. *(RecalcConfig 필드를 config 키명(`control_limit_k_sigma`)으로 만들면 `LimitConfig` 속성(`k_sigma`)과 어긋나 첫 줄에서 AttributeError — 필드 복제 대신 기존 LimitConfig 재사용으로 산식 파라미터 단일 소스 유지.)* 아래 표는 **로드 대상 키**:

| `limit_engine` | `recalc_deadband_k_se` ★신규 | 2 | dead band = k×SE |
| `spc` | `trim_quantile`·`q_low`·`q_high`·`min_group_n` | — | 산식·분위수·소표본 가드 |

- 명명 상수: **`EPS`는 `config_util` 등 공용 위치에 1개**(리뷰 L7 — `tttm_engine.py:32`에 이미 `1e-9`가 있어 recalc에 또 정의하면 값이 갈릴 수 있음). status 리터럴(`AUTO_APPLIED`/`PROPOSED`/…)·`TRIGGER_PERIODIC`도 **모듈 상수화**(리뷰 L5 — `seed_control_limits.LIMIT_VERSION`·`TRIGGER_INITIAL` 선례).
- **행 q vs config q 검증(리뷰 M3)**: robust σ는 `config.k_sigma`로 역산하는데 분위수 밴드는 **행 단위 carry**(시딩이 CSV 값을 그대로 실음 — `test_seed_control_limits`가 "하드코딩 아님"을 assert). 행 `q_low/q_high`가 config와 다르면 σ_ref가 조용히 틀어지므로, **Task 0에서 v1 시딩 행의 q값 == config q값을 데이터로 assert**(또는 불일치 시 robust σ 무효 처리)한다.

> ⚠️ **계층 2는 실 DB 필요 → 무DB 시 skip 가드(리뷰 L4)** (tttm 테스트 패턴). `delta_sigma`는 upstream 반영 완료라 sync된 DB면 존재하나, 미sync 로컬 대비 컬럼 부재 시에도 skip으로 우회.

## 8. 엣지케이스 & 가드

- **NaN/None 값(L11)**: 판정 **최상단에서 필터** → `n_used` 재계산 후 소표본/판정 진행.
- **소표본**(n_used<min_group_n): interval=window=500이라 정기 경로 무발동이나 방어(결정 4-c) — skip+로그.
- **sigma_ref≤EPS**(zero_sigma·q밴드 붕괴): no_change(degenerate).
- **resolution None/≤0**: res_σ=0(항 skip), dead_band는 2×SE 하한 유지(§3-3).
- 🔴 **양자화 그룹 자동 불가 (리뷰 H5 — 실측)**: `res_σ ≥ reset_delta_max_sigma(0.5σ)`면 `dead_band = cap_1 = res_σ`가 되어 **자동적용 구간이 산술적으로 소멸**한다(이동량이 정확히 res_σ일 때만 auto = 사실상 불가). 실측상 감시 45그룹 중 **15그룹**이 해당(`C32 step5` res_σ≈3.18 · `C63 step6/7`은 n_distinct=**2** 등 — 값이 2~5개뿐인 이산 센서라 "한 칸 이동"이 이미 0.5σ를 넘음). → **`no_change(resolution_bound)` + 로그로 자동 대상에서 제외**하고, 필요한 재산정은 승인 경로로만. *(결정 4-a의 "시뮬은 연속적이라 분해능≈0" 전제는 실측과 반대였음 — 4-a 한계 문단 갱신 대상.)*
- **reset_ref.sigma_ref≤EPS**: 리셋 지점 퇴화 → 누적 판정 불가 → **보수적으로 needs_approval**(자동 금지) + 로그. (드묾 — 리셋 지점은 승인·수립 행이라 σ>0 전제.)
- **분위수 표본 민감성**: q 극단치는 표본 민감(회의안건 §1-6) → dead_band 흡수. 충분성 W7 관측.
- **current 없음**(신규 그룹): 상류가 whitelist∩control_limits로 필터(loader).
- **delta_pct center_before≈0**: NULL(0 나눗셈 가드, L10).
- **부동소수**: 반올림 없이 재현성 유지.
- 🟡 **밴드 폭(σ) 상한 미도입 — 기록 후 실측 설계 (리뷰 M8, B안 채택)**: `cap_1`/`cap_cum`은 center 이동만 본다. σ 확대로 밴드가 넓어지는 경로는 두 가지인데 — ⓐ **급격형**(σ 급증)은 대개 이상 신호라 §3-6 **무이상 게이팅이 1차 차단**하고, ⓑ **점진형**(매 회 소폭씩 누적)은 *1회 변화율 상한으로는 원리적으로 못 막는다*(1.05배×20회 = 2.6배인데 매 회는 어떤 임계도 밑돎). 즉 1회 상한은 이미 게이팅이 막는 쪽만 중복 방어하고 **정작 사각지대는 못 잡으므로**, 근거 없는 임의 임계를 넣는 대신 **기록 → 실측 → 누적 기준 설계** 순서로 간다.
  - **기록(스키마 무변경)**: `sigma_after/sigma_before`와 **리셋 지점 대비 누적 σ 비율**을 로그로 남긴다. 별도 컬럼 불요 — 밴드 폭은 `limit_corrections.ucl_after − lcl_after`, 이전·리셋 시점 값은 **control_limits 버전 이력(is_active=false 행 보존)**에서 산출 가능.
  - **W7 Scorecard 채점 항목에 "밴드 폭 추이"를 명시** — 백로그 매몰 방지(§9 이월).
