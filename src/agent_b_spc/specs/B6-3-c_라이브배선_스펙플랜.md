## 1. 목적 · 경계

a·b는 **주입식 순수 코어**(트리거·부작용을 주입받음)라 스스로 라이브로 못 돈다. c는 이들을 **기존 `spc_consumer`에 얹어** 실제 Kafka 스트림으로 구동하고, a·b가 비워둔 seam(writer·reload·tttm·persist·버퍼)을 실 구현으로 채운다.

- **경계(IN)** = ① `spc_consumer` 확장(a·b 인스턴스 보유·구동) · ② `fdc.agent`(QualVerdictConfirmed) 구독 · ③ a·b seam 실 구현(provisional write·reload·set_excluded·버퍼·persist) · ④ firm apply 확장(_handle_correction) · ⑤ `get_phase` 제공(억제 게이트 입력)

## 2. 배선 맵 (seam → live) — 이 문서의 핵심

### 2-1. 이벤트/토픽 → 엔진 호출

| 소스 | c 핸들러 | → a·b 호출 | 상태 |
|---|---|---|---|
| `fdc.raw` pm_count↑ | 기존 wafer 처리에서 감지 | `a.on_pm(chamber, pm_count)` | fdc.raw에 pm_count 존재 ✅ |
| `fdc.raw` wafer 완료 | 기존 wafer 버퍼→Point | `a.on_wafer(chamber, wafer_id, points)` + **버퍼 축적** | 컨슈머가 이미 wafer 집계 ✅ |
| `fdc.agent` QualVerdictConfirmed | **신규 구독**(3토픽) | `a.on_qual_verdict(chamber, verdict)` | ⚠️ 발행 미구현 → **mock**(결정4) |
| `a.PHASE2_SIGNAL` 반환값 | on_wafer 반환 처리 | 표본 충분 시 `b.on_phase2_signal`→패키지 제안 | select None이면 대기 |
| `fdc.correction`(승인 firm) | 기존 `_handle_correction` **확장** | apply(관리선)·완료 시 후속(아래) | apply 경로 live ✅ |
| `ChamberRequalified` | **신규 구독** | 챔버 후속 1회: `a.on_firm_established`·rebase·Y write·verify 시작 | ⚠️ 미구현 → mock/fallback(결정6) |
| (매 wafer) | — | `a.get_phase(chamber)` → **B4-1 억제 게이트 입력** | B4-1 대기 |

### 2-2. a·b seam 실 구현 (주입식 → 라이브)

- **a.writer.write_provisional** — provisional 관리선 control_limits write (version bump·deactivate·INSERT — a §3). recalc_writer 패턴 재사용
- **a.reload** — `reload_limits`(B5-1a seam) 그대로
- **a.tttm.set_excluded** — TTTMEngine 인스턴스의 set_excluded (union 전달)
- **a.persist/load** — **결정2 ⓓ: 신규 저장 없음.** restore는 재시작 시 **control_limits(provisional active)·limit_corrections(PROPOSED)·quals 파생**. post_pm_count는 리셋 수용
- **b.buffered_wafers** — **결정3: c 인메모리 backward 버퍼**(정착 값 N=500, provisional 챔버만). 센서 원값 저장 테이블 없어 인메모리가 유일
- **b recent_predictions(Y용)** — **결정3(C-2·ⓑ): 인메모리 버퍼 아님 → apply 시 `wafer_predictions` 최근 N행 read**(A 적재분·과거값이라 누수 안전). `predicted_c65`는 fdc.raw에 없고 컨슈머 미구독이라 라이브 버퍼 불가·불요
- **b.verify forward** — **결정3: 버퍼 아님, tally.** firm 후 라이브 위반을 30장까지 카운트(flagged/30)
- **b.write_y_threshold** — `y_thresholds` write (테이블 PM 승인 후)
