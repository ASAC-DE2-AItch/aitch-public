## 1. 요구 (상시 + 실행 중 주입 + 컷 간 잔류 승계)

기존 시뮬은 **일회성**이었다: `SimulatorRunner`가 S11 클릭마다 `--scenario X.yaml`로
sim 프로세스를 **새로 spawn** → 매 컷이 월드스테이트를 리셋한다. 4컷 데모는 1막(CH3 드리프트→
관리선 재설정)이 2막 배경으로 **유지**되어야 하는데(§0-2 "CH3 알람 0건이 배경 증거"),
프로세스가 리셋되면 이 잔류가 깨진다.

개조 3요소:
1. **상시프로세스** — sim이 계속 돌며 4챔버 baseline 발행
2. **실행 중 주입** — 도는 중 S11 클릭으로 시나리오 주입
3. **컷 간 잔류 승계** — 주입 효과가 원복되지 않고 다음 컷 배경으로 승계

## 2. 구현 — 월드스테이트 모델 (`scenario_injector.py`)

핵심 통찰: 주입 효과는 이미 `k = ch_wafer_index − start_after_wafers`의 **순수 함수**이고,
`shift`·`drift`(램프 후 유지)·`pm_reset`(level_shift)은 **k가 커져도 값을 유지**한다.
즉 하나의 지속 injector에 시나리오를 **남겨두기만** 하면 잔류는 산식상 자동이다 — 개조는
"런타임에 시나리오를 추가"하는 것으로 환원된다.

추가 API:
- `inject_now(sc, at_index)` — `start_after_wafers`를 현재 순번으로 스탬프해 장전(사본 —
  원본 YAML 불변). S11 라이브 주입의 코어. 이후 효과는 `at_index`부터 시작·유지.
- `active_summary(idx_by_chamber)` — 챔버별 현재 활성 시나리오(원복 금지 가시화·판정 소스).

## 4. 프로덕션 배선 (2026-07-28 — 같은 날 2차 커밋으로 구현 완료)

당초 "설계만" 남겼던 배선을 파일드롭 방식으로 구현. **체인 dry-run이 이 프로덕션 채널을
그대로 통과**(`--inject-via files` 기본값)하므로 주입 경로는 브로커 없이 검증됐다.

1. **`InjectControl`** (`src/simulator/inject_control.py`) — `control/inject/*.yaml` 폴링 →
   `normalize_scenario` → `inject_now(대상 챔버 현재 순번 max)`. 처리 파일 processed/,
   실패 파일 failed/ 이동 + 로그 (루프 불사 — 헌법 6-2). utf-8-sig 읽기 (PS1 BOM 교훈 §7).
2. **producer 상주 대기** — `kafka_producer.run()`이 `--scenario` 없이도 빈 injector로 기동,
   wafer마다 `ctl.poll(idx_by_chamber)`. 설정 = params `simulator.inject_control` (6-1).
3. **`SimulatorRunner` 상주화** — RUN: 세계 없으면 baseline 기동(`--inject-control`,
   persistent_run 기본값) 후 시나리오 yaml을 control로 **드롭**, 있으면 드롭만
   (응답 `mode`=started+injected/injected). STOP만 세계 종료. RunnerBusy 미발생(호환 보존).
4. **S11 프론트** — 실행 중 비활성화 제거: 버튼이 "주입 ▶"로 바뀌고 클릭=드롭.
   툴팁으로 잔류 승계(원복 금지) 명시.
