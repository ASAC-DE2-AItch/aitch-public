# RTD 자동 정지 승격 설계 v1 — "정지는 자동, 해제는 사람" (2026-08-06)

> 근거: 멘토 8/5 확정 — **현업 RTD는 자동 정지가 맞고, 챔버 단위가 디폴트** (up 시 샘플 확인 관행 +
> rolling plan 생산 조절 → 오정지 비용 낮음). 업계 정식 명칭은 FDC interdiction / tool inhibit + OCAP.
> 현업 표준 패턴: 위반 → 자동 inhibit → 조사·해결 → **사람이 해제**. 우리 구조와 정확히 정합.

## 0. 핵심 판단 — 새 기능이 아니라 "연결 4개"

부품이 전부 이미 있다. 승격은 기존 부품을 잇는 작업이다.

| 필요 부품 | 현재 상태 |
|---|---|

## 0-B. 스코프 2단 — 챔버 / 장비 (멘토 8/6 추가 확인 · 구현 완료)

멘토: **"챔버 단위로 정지하지만 장비 단위로도 정지한다."** 현업에서 장비를 통째로 세우는 경우는
**공용 설비(가스·전원·냉각) 공통 원인**일 때다. 우리 시스템엔 이미 그 신호가 있다 —
**RTD 경로① `tttm.reference_suspect`**(fleet median 자체 오염 = 여러 챔버 공통 이동).
기존 RTD 배너 문구가 이미 "챔버 개별이 아닌 **장비 단위 사건 신호**"라고 쓰고 있었고,
이번 승격으로 그 문장이 실제 동작이 됐다.

| 스코프 | 발동 신호 | 물리 의미 | 대상 |
|---|---|---|---|
| **chamber** (디폴트) | CRITICAL + **동시 위반 센서 2종 이상**(`violations[].sensor_id` distinct) | 그 챔버만의 이상 | 해당 챔버 |
| **equipment** | 위 + **`tttm.reference_suspect=true`**(= `suspect_sensors≠∅`) | 공용 설비 공통 원인 | 형제 챔버 전체 |

> **⚠️ 초판 정정 (2026-08-06, B 리뷰)**: 초판은 챔버 조건에 `tttm.suspect_sensors` 개수를 썼는데,
> 그 필드는 **`reference_suspect`를 발생시킨 공통 이동 센서 목록**이라 두 값이 논리적으로 동치다
> (`suspect_sensors≠∅` ⟺ `reference_suspect=True`). 따라서 초판의 "suspect_sensors≥2 **AND**
> reference_suspect=false"는 **성립 불가능한 조합**이었고, 의미도 반대였다(장비 신호를 챔버 재료로 사용).
> 정정: **챔버 = `violations` distinct 센서 수**(그 챔버 고유 SPC 위반의 폭) /
> **장비 = `reference_suspect`·`suspect_sensors`**(공통 이동). 두 재료는 원인 계층이 다르다.

**구현 원칙 — 장비 정지도 행은 챔버별로**: `scope='equipment'` + 같은 `incident_id` 로 묶는다.
덕분에 신호 파일(챔버별)·시뮬 스킵·해제(requal 하류)·감사 경로가 **전부 무변경 재사용**된다.
**해제 대칭**: 장비 스코프 행의 requal 해제는 **같은 발동 incident 의 형제 행 일괄**이다 —
공용 설비 원인의 해소 확인은 장비 전체의 재가동 근거이기 때문(챔버 하나의 requal 로 장비를
되살린다 — 멘토 "up 시 샘플 확인" 관행 정합). 이 확장이 없으면 형제 3챔버가 영구 정지로 남는다.
스위치 `rtd.allow_equipment_scope`(기본 true) — false 면 항상 챔버 단위로만(보수 운영).
DB = 마이그레이션 `0007`. API `/chambers/status` 는 `scope`·`equipment_id`·`equipment_inhibited` 를 낸다.

## 1. 3층 구조 (현업 OCAP 매핑)

```
L1  알람          fdc.alert → 기록·Agent 리포트          (현행 그대로)
L2  자동 조치     ① wafer HOLD (B9 — 검증 완료)
                  ② 챔버 inhibit (★이번 승격분 — 자동)
L3  해제          R9 requal 승인 → ChamberRequalified → inhibit 해제  (사람)
```

## 2. 발동 규칙 (보수적 시작)

- **조건**: `severity == CRITICAL` 마커 알람 **AND** `suspect_sensors ≠ ∅` (#113 필드 — 순정상 suspect=0
  게이트 실증이 선결이므로 오발동 방어가 곧 머지 게이트와 동일).
- **스코프**: `alert.chamber_id` 한 챔버만 (멘토 디폴트 — 장비 전체 아님).
- **디바운스**: 이미 inhibited인 챔버는 무시. Incident당 발동 1회 (그루퍼의 chamber+시간창 그룹핑 승계).
- **실행 주체**: **orchestrator (PM 소유)** 가 CRITICAL 마커를 구독·실행 — `src/agent_b_spc/` 무수정
  (소유권 충돌 없음, B 몫은 #113 그대로).

## 3. 상태·배선

**DB**: `chamber_inhibits` 신규 테이블 + 마이그레이션 (3-2 규약 — init.sql·migrations 같은 PR)
```sql
chamber_inhibits(id, chamber_id, incident_id, inhibited_at, trigger_alert_id,
                 released_at NULL, released_by NULL, release_qual_id NULL)
```
→ 열린 inhibit = `released_at IS NULL`. **이 테이블이 그대로 uptime 위젯(#75)의 데이터 소스**
(inhibit 구간 = downtime — 멘토 제안 2건이 한 테이블로 해결).

**물리 정지 (시뮬 세계)**: orchestrator가 `control/inhibit/SIM_CH_N.json` 드롭 → 시뮬레이터가
poll (InjectControl 패턴 재사용)하여 **해당 챔버 wafer 생산 중단** (rolling plan 정합 — 멘토).
해제 시 파일 제거 → 재개. 시뮬 수정은 PM 소유(3-1) ✓.

**해제**: R9 requal 승인 → `ChamberRequalified` → orchestrator가 `released_at`·`release_qual_id` 기록
+ inhibit 파일 제거. **자동 해제 경로 없음** — 해제는 예외 없이 승인 하류만.

**화면 (S1)**: 챔버 카드 상태 배지 `● RUNNING` / `■ INHIBITED (hh:mm~, INC-…)` + uptime %.

## 4. 헌법 정합 (개정 1건 필요 — PM 승인 사안)

1-1 승인 필수 목록(Recipe·실력치·정비 권고·처분)에 "챔버 정지"는 **없다**. 자동 inhibit는
ⓐ 물리 세계를 바꾸는 조치가 아니라 **보수적 안전 정지**(생산만 멈춤)이고 ⓑ 가역적이며
ⓒ 해제가 승인 게이트(R9) 하류에만 있으므로 Model R2R과 같은 "자동 허용 + 기록 + 상한" 논리가 성립.
→ **CLAUDE.md 1-1에 예외 4 신설 제안**: "챔버 inhibit(안전 정지)는 CRITICAL+suspect 조건에서 자동
허용 — 단 `chamber_inhibits` 기록 필수, 해제는 requal 승인 하류만, 오발동(순정상 정지) 1건 실증 시
제안 모드로 회귀" (1-1 예외 2의 '가드 걸고 허용' 선례).
