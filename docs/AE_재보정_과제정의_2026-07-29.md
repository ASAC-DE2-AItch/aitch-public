## 1. 증상 (실측)

7/29 완전 리허설(`LEAN85_AE_MODE=live`)에서 **예측 40건 전부 `ae=1.000 drift=1.000`**.
높은 게 아니라 스케일 천장에 클램프된 상태다 — calib 최상단 앵커(1.0 = P99.9, ae_raw 399)를
전부 넘었다는 뜻. 정상 wafer라면 중앙값 0.05(P50) 근처여야 한다.

- 주입 없는 챔버 포함 **4챔버 균등 포화** → 주입 탓 아님
- predicted_c65는 981~1054 정상 대역 → **예측 축은 무관, AE 축만의 문제**
- drift는 ae의 파생값(`(EWMA−B0)/(alarm−B0)`)이라 **ae 하나 고치면 같이 풀림**

## 2. 원인 (구조)

**AE가 학습한 세계와 서빙 세계가 다르다.** AE(z16_rev3_seg1)는 **원본 데이터**(오프셋 없음,
단일 챔버)로 학습·보정됐는데, 시뮬레이터는 그 위에 **챔버 개성**을 입혀 발행한다:

- 챔버×센서마다 고정 오프셋을 **독립 추첨** (N(0, 0.5σ), seed 42) + 소노이즈(0.05σ)
- 실측 오프셋 크기: 전 센서 평균 0.21σ, 최대 0.41σ(C11) — **크지 않다**

크지 않은데 왜 천장까지 가나: AE는 conditioned **Mahalanobis** — 센서 간 상관구조를 학습한
거리다. 실제 챔버 개성은 물리로 엮여 상관 일관적으로 밀리지만(매칭 네트워크가 다르면 RF 계열이
**함께** 이동), 우리 오프셋은 센서별 독립이라 **상관을 깨는 방향의 조합**이 된다. 개별 크기
0.3σ는 무해해도, 83개 피처가 "있을 수 없는 밸런스"로 지속되면 합산 거리가 폭발한다.
파형(시간 동역학)은 실측 그대로다 — 깨진 것은 **센서 간 레벨 조합**뿐이다.

예측(XGBoost)이 멀쩡했던 이유: 센서를 하나씩 보는 구조라 밸런스에 둔감. 상관을 보는
소비자는 AE가 처음이라, 이 간극이 지금 드러난 것이다.

## 4. 해결 — 재보정 (모델 분리 아님)

**PM 결정(7/29): 챔버별 모델 분리·시뮬 재시딩은 하지 않는다.** 4챔버는 같은 원본의 사본이라
분리 학습은 정보 이득 0이고, 재시딩은 B 검증 재확인 + E2E 재검증을 수반하면서도 재보정을
없애주지 못한다. **재보정은 시뮬 세계가 보정 데이터에 들어가는 순간 정의상 해결된다.**

채점 경로에서 어디까지 다시 만드느냐 — 3수준:

```
트레이스 → 피처(83) → 스케일러 → AE 재구성 → 잔차
  → Mahalanobis (scorer.npz)   = ae_raw
  → 앵커 변환 (calib.json)     = ae_score [0,1]
```

| 수준 | 재산출 대상 | 충분 조건 | 소요 |
|---|---|---|---|
| ① calib만 | 앵커 5개 (P50/P90/P98.5/P99.5/P99.9) | 시뮬 세계에서 ae_raw의 **순위가 살아있을 때** (값만 전체 상향) | 반나절 |
| ② scorer+calib | 잔차 공분산 + 앵커 | ae_raw 분포가 뭉개졌을 때 — 오프셋 조합을 "정상" 공분산에 편입 (**유력**) | 1일 |
| ③ AE 재학습 | 가중치까지 | ①②로 분별력 불충분 시 (CT②의 축소판) | 2일 |

## 5. 절차 (분담 포함)

1. **[PM 지원] 정상 세트 생성** — `python scripts/dump_ae_input.py --per-chamber 250`
   → `Data/ae_repro/ae_input_sim.csv`(시뮬 발행값)·`ae_input_control.csv`(원본 대조군).
   seed 고정이라 리허설 당시 값 그대로 재현. 주입 미포함(정상만).
2. **[A] 진단** — 두 파일의 **ae_raw 분포** 비교:
   - control 정상 + sim 포화 → 원인 = 오프셋 확정 → ②
   - sim에서 raw **순위 유지** → ①로 충분
   - 둘 다 포화 → 오프셋 무관(seg·피처 파이프라인) → 별도 규명 후 재판단
3. **[A] 재산출** — 새 번들은 **별도 디렉토리**(`anomaly_ae/ae_v2` 또는 `calib_v2` —
   덮어쓰기 금지, 4-1) + `models/CHANGELOG.md` 기록 (3-3).
4. **[A] 분별력 검증 — 성공 기준 3개 (전부 충족해야 통과)**:
   - ⓐ 시뮬 정상 wafer: ae_score 중앙값 ≈ 0.05, 0.2 초과 ≈ 1.5% 이내
   - ⓑ 주입 이상(스파이크·스톰): 정상 대비 뚜렷이 높은 점수 (랭킹 분리)
   - ⓒ Qual 기준 0.2로 조용/요란이 실제로 갈림
   **3개 중 하나라도 실패 → PM에 보고. 그때 시뮬 재시딩(상관 보존 오프셋)이 2순위로 승격**
   — 판단 창구는 8/3, E2E(8/5) 전이 마지막 갈아탈 기회.
5. **[A] 배포·확인** — 번들 교체 + 스택 재기동 → `rehearsal_check.ps1` `[8]`에서
   anomaly 분포 정상화 확인 (기존 도구 그대로).
6. **[PM] 후속 스위치** — 새 calib에서 **P98.5·P99.5 값을 읽어**
   `ct.ae_anomaly_threshold`·`spc.crazy_wafer.anomaly_score_min` 등재.
   이 등재가 세 가지를 동시에 켠다: SCRAP 자동 권고(C STEP 4) · RELEASE 가드(C STEP 2 신설)
   · B publisher 절대 키 전환(B ①→② 순서). 등재 전까지 셋 다 안전하게 대기 상태.

## 6. 한 줄 요약

**AE는 고장나지 않았다 — 배운 적 없는 세계를 채점하고 있을 뿐이다. 시뮬 세계를 보정
데이터에 넣어주면 끝나는 문제고(①~③ 중 진단이 고르는 수준), 그 완료가 SCRAP 개통·RELEASE
가드·컷 전환의 공통 선행 조건이다.**
