## 디자인 원칙 (2026-07-11 확정 — Lock, v1.3 개정 / **v1.5 셸·테마 개정**)

> 근거·수집 원문: `references/프론트_UIUX_레퍼런스_수집_v1.md` (P1~P10 + §7 AI 판박이 진단). 여기엔 결론만.

**셸 문법 (v1.5 확정 — PM 제공 Travo형 레퍼런스 이미지)**
- **상단 필-탭 내비 (사이드바 폐지)**: 좌 로고 → 중앙 **필(pill) 탭** 나열(액티브 = **솔리드 블랙 필 + 흰 글자**, 비활성 = 라이트 그레이 필) → 우측 원형 화이트 아이콘 버튼(설정·알림·아바타). **시뮬레이터 탭은 우측 아이콘군 옆 분리 배치**(테스트 하네스 구분 유지).
- **툴바 2행**: 내비 아래 전역 검색바(좌, 라이트 그레이 라운드) + 정보 칩 우측 정렬 — `라벨: **볼드값**` 패턴 (예: `교대: B조` `Cycle: 424` `Critical: 1`).
- **카드**: 보더리스 화이트, **radius 대(≈24px)**, 매우 미세한 섀도 — 캔버스(웜 오프화이트)와의 **톤 차이로 분리**. 카드 내부 행·입력은 라이트 그레이 필(r14).
- **상태 필**: 진행중/액티브 = 블랙 솔리드 필, 대기 = 그레이 아웃라인 필. 블랙 = "액션·현재" 중립색.

**정체성: "정밀 계측 (Precision Instrument)" — 자이스 척추** *(v1.3 확정 — PM 선정 레퍼런스 3종: Carl Zeiss metrology portal / AURA DePIN / GeoTab Insurance, v1.5에서 Travo형 셸 문법 흡수)*
- **척추 = 자이스**: 압도적 여백 + **물리 장비(챔버)를 렌더된 물체로 크게** + 번호 핫스팟·리더라인·치수 주석 + near-monochrome 절제. "진짜 정밀 장비 회사" 인상. 우리 도메인(계측)과 직결.
- **AURA에서 흡수**: 렌더 옆 **거대 tabular 숫자**(주인공급) + 델타/스파크라인 = "물체 + 살아있는 데이터" 공존. 챔버 렌더는 실빌드에서 **Three.js 3D**(광택 질감의 유일한 길), 1차는 SVG 단면.
- **GeoTab에서 흡수**: `// 01` mono 섹션 리듬 + 거대 타이포 서사 — 결정 큐·S4 Brief를 "근거→추천→승인" 내러티브로.
- **AI 판박이(클로드 룩) 금지 조항**: 틸 그라디언트·글로우·깜빡이는 점·컨테이너 수프·전부대문자 라벨 남발 금지 (§7 체크리스트로 자가진단). **액센트 색 = 미정 스와프 토큰**(near-monochrome 우선, 색 결정은 별도 승인) — 보라/틸 금지.

**공통 규율**
- **테마**: 다크·라이트 둘 다 제공하되 **라이트 우선 개발 (v1.5 전환 — 구 "다크 우선" 폐기)**. 라이트 = 기본값·시연 테마 (캔버스 = 웜 오프화이트 #ECEEF2 계열), 다크는 후순위 변주. 수동 토글은 `localStorage`(`index.html` FOUC 스크립트가 단일 소스).
- **다크 변주 시 배경 = 다크 그레이(#0E~#1A 계열), 퓨어 블랙(#000) 금지** (ISA-101 High-Performance HMI — 무채색 중간 회색 원칙).
- **색은 의미에만** (P1): 정상은 무채색, severity·drift·확신도·상태에만 유채색. 장식색 금지(경보색과 주의 경쟁).
- **결론 먼저 + 점진적 공개** (P2): 추천/판정 먼저, 근거는 펼쳐보기 (S4 Brief 골격).
- **예측 ≠ 사실** (P3): 예측·확신도는 측정값과 시각 분리, 확신도는 %가 아니라 색 밴드/등급.
- **센서 표기**: 표시명 + C코드 병기(예: `Gas flow C4`) — 판정 로직은 C코드, 표시 계층만 변환(헌법 6-4).
- **첫 화면 밀도**: above-the-fold, 주 블록 **≤8**, "need-to-have"만 (Datadog 과밀 반면교사).

## S0. 공통 레이아웃

- **상단 필-탭 내비 (v1.5 — 사이드바 폐지)**: 좌 로고+heartbeat 필 → 중앙 필 탭(모니터링·SPC 차트·인시던트·승인·Disposition·Qual·KPI — 액티브=블랙 필) → 우측 원형 아이콘(알림 badge=Pending 승인 건수, 클릭→S3 · 테마 토글 · 아바타) + **시뮬레이터 분리 탭**
- **툴바 2행**: 전역 검색(챔버·인시던트·센서) + 정보 칩 우측 정렬 — `교대: B조` `Cycle: N · Synced` `마지막 수신: hh:mm:ss` (Equipment/Chamber 필터·조회 기간은 칩 클릭 드롭다운으로 흡수)
- **Agent Copilot 독(dock)**: 우측 상시 접이식 패널(S9). 전 화면에서 열림. 현재 chamber 필터·라우트(보고 있는 Incident/차트)를 **컨텍스트로 자동 주입** — "이 챔버 왜?" 하면 대상 자동 스코프.
- **기술**: React SPA + FastAPI (REST + WebSocket/SSE). 라우팅은 화면 단위(S1~S10), 전역 상태는 chamber 필터·pending badge·heartbeat·**테마·Copilot 컨텍스트**.
- **엣지**: heartbeat 끊김 시 전 화면 상단에 경고 배너 ("감시 시스템 이상 — 데이터 신뢰 불가")

## S1. 실시간 모니터링 대시보드 *(v1.3 전면 재구성)*

**목적**: 열자마자 2초 안에 ① 지금 라인이 건강한가(상황인지) ② **내 결정이 필요한 게 뭔가**(액션). 교대 인수인계의 첫 화면.

**스케일 규칙 (v1.6 — 챔버 내비의 실서비스 확장)**: 챔버 레일/스트립은 **"현재 스코프의 챔버 전부"**를 의미한다 (스코프 = Fab → Bay → Tool 계층, 레일 상단 스코프 선택기로 전환). **스코프 선택기는 Bay(이하)만** — Fab은 전역 컨텍스트로 고정(라벨 표시)하고, 팹 전환은 사실상 테넌트 전환이므로 프로필/전역 메뉴 소관 (백엔드도 단일 팹 가정 — chamber_id에 fab 차원 없음). 데모 4챔버 = Tool 스코프 1개(ETCH-01, 장비 1대=4PM — v1.3)의 working set. 스코프 내 챔버가 화면을 넘으면 **worst-first 정렬 + 스크롤 + Critical 자동 부상**(management by exception, ISA-101) — 전체 열거는 하지 않는다. Fleet 전체 헬스는 요약 카운트(정상 N·주의 N·Critical N)로만.

**배치 (v1.5 — Travo형 3열, 상단 필-탭 아래)**: 좌 대형 카드 = **③ 포커스 챔버**(부유 정보카드 + 하단 부유 툴바 + 핫스팟) · 중앙 열 = **SPC 편차 바차트**(의심 윈도우 하이라이트 + 콜아웃 툴팁) 위 + **② 결정 대기 큐**(행 리스트: 시각·담당 아바타·요약·상태 필) 아래 · 우측 열 = **① 챔버 6 타일**(썸네일 그리드 — 전부 보임 유지 + 선택 챔버 스탯 + 브리핑 열기) 위 + **Ⓒ Copilot 카드**(+ ⑤ 처리 스탯 3종) 아래. ④ VaR은 우측 열 스탯 or 정보 칩으로 흡수. *(5블록 내용 불변 — 배치만 개정)*

### S4-b. CT²(AE) 배포 승인 브리프 *(2026-08-09 신설 — `docs/CT2_게이트_기준_개정_v2_2026-08-09.md` §7)*

**언제**: PENDING 행의 `request_type == "ct2_deploy"`. Incident 알람 승인이 아니라 **모델 게이트**(계약 §8-E)이므로 위 4지선다 구조를 쓰지 않는다.

**왜 신설**: 그동안 이 건은 정의가 없어 S4 폴백으로 흘러 `승인 대기 · <번들명>` **한 줄**만 떴다. 승인자가 "어떤 항목이 기본값보다 느슨한 채 PASS 했는지"(헌법 3-3 ③ ⓑ)를 볼 수 없었고, `validate_bundle`이 "승인 브리프에 노출된다"고 적어 둔 `_weakened`는 실제로는 **stdout 로그에만** 있었다.

| 구역 | 표시 항목 | 출처 |
|------|-----------|------|
| 헤더 | `CT²(AE) 배포 — 게이트 <PASS/FAIL/SKIP>` · 번들명 | `ct2_verdict` · `ct2_bundle` |
| **약화 조건** | 건수 + 항목별 `<라벨> — 기본 X → 현재 Y · <사유>`. 예산 완화에는 **가드 문구 병기**(미탐 1건 → 0.02 복귀 + 원인 규명 전 재완화 금지) | `ct2_brief.weakened[]` |
| **경계 라벨** | 항목별 `PASS-경계`/`FAIL-경계` + 관측률 · CI · 예산. "표본이 작아 '예산 이내'가 확정이 아님"을 명시 | `ct2_brief.boundaries[]` |
| **잔여 리스크** | E1 미실행(정답지 부재) · SKIP 항목 · 경계 라벨 종수 | `ct2_brief.residual_risks[]` |
| FAIL 항목 | 떨어진 검사명 (FAIL 상태 번들은 자동으로 승인 요청이 열리지 않는다 — 헌법 1-4) | `ct2_failed_checks[]` |
| 브리프 부재 | 구 리포트(schema v2 이하)·리포트 부재는 **경고로 표시** — 빈 화면이 "약화 0건"으로 읽히면 안 된다 | `ct2_brief_missing` |

**결정 액션 = 2지선다**: 승인 / 반려만. `modify`·`escalate`는 서버가 400으로 거부한다 (번들은 수정 대상이 아님 — 계약 §8-E).

**문구의 정본**: 모든 한국어 라벨·사유는 `validate_bundle.build_approval_brief` 산출(`report.approval_brief`)이다. gateway `attach_ct2_brief`는 `ct2_*` 키로 **평탄화만** 하고 화면은 그대로 렌더한다 — 화면이 키 이름을 번역하기 시작하면 임계를 바꿀 때 두 곳을 고쳐야 하고 **안 고쳐도 아무 일도 일어나지 않는다**(헌법 7장).

**동작 원칙**
- **신규 추론 엔진 아님.** 기존 Agent Tool API 재사용(search_similar_cases, get_spc_status, get_incident_brief 등)을 대화형으로 오케스트레이션만. 이미 생성된 리포트/근거를 자연어로 surface.
- 응답은 **텍스트 + Evidence Card**(유사 Case·SHAP 바·출처 링크) 혼합 — 근거 없는 단정 금지, 항상 출처 표기.
- 읽기 전용. **승인·판정·조치는 Copilot에서 불가** — "승인하려면 S4로" 딥링크만 제시(원칙 ①: 액션은 정규 UI 게이트로만).

**API**: `POST /agent/query` (payload에 `context: {chamber, incident_id?, sensor?, range?}` 포함)
**엣지**: LLM 호출 실패 시 fallback 메시지(헌법 6-3, JSON 강제·재시도 2회). 컨텍스트 없이 전역 질의도 허용.

| 구역 | 표시 항목 |
|------|-----------|
| 시나리오 리스트 | 카드형: 이름, 설명, 대상 chamber, 주입 패턴 요약, **정답 라벨(공개)**, 예상 소요 |
| 실행 상태 | 진행 타임라인(주입 이벤트 표시), 재생 위치, 발행 rate, 배속 조절 |
| 주입 로그 | sim_events 실시간 뷰 |
| **Scorecard 탭** | 종료 시나리오별 "주입 정답 vs 시스템 판정" 대조 (감지 지연, Incident 수, 라우팅 일치, Disposition 일치, Qual 판정) — 시연 마무리 화면 |

**액션**: 시나리오 선택 → 실행/중지, 배속 변경, 데모 리셋. **API**: `GET /sim/scenarios`, `POST /sim/trigger`, `POST /sim/stop`, `POST /sim/speed`, `GET /sim/status`, `GET /sim/events`, `GET /sim/scorecard`

**경계 (필수)**: S11의 모든 API는 **데이터 생성(fdc.raw 위쪽)만** 제어. 판정·Incident·승인 상태는 조작 불가. 파이프라인은 sim_events를 읽지 않음 (답안지 커닝 금지).
