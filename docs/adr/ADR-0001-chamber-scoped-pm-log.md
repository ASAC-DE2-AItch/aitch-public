# ADR-0001 — pm_log 챔버 스코프: 단기 전역 유지, 챔버별 필터는 후속 전환

- **Status**: Accepted (단기 전역 유지) · 후속 전환 **Proposed — 일정 미정(A 협의 대기)**
- **날짜**: 2026-07-28
- **담당**: 결정 = A(팀원 A)·B(팀원 B) 합의 / 후속 전환 구현 = **A**
- **관련**: 계약 §8-B-1(알려진 한계) · `src/agent_b_spc/specs/B6-3-f_요란판정_pm_log_기입_스펙플랜.md` §2 D5 · B6-3-f PR(A 조건부 승인 조건 ②)

## Context

B6-3-f로 요란 판정 확정 시 B가 `pm_log.json`에 PM 1건을 append하게 되면서, 엔트리에 `chamber_id`가 처음으로 실린다. 그런데 **소비측 A는 챔버 축을 보지 않는다**:

- `lean85_pipeline._meta_features` :245 — `parse_pm_log`가 준 `(시각, type)`만으로 `days_since_last_pm`·`is_high_regime`·`high_regime_days`·`dslp_x_hour`를 만든다. wafer가 어느 챔버인지와 무관하게 **직전 PM 하나**를 본다.
- `should_retrain` :445-448 — 신규 PM **날짜**가 있으면 이벤트 재학습 트리거. 여기에도 챔버 축이 없다.

즉 `chamber_id`는 기입되지만 **읽히지 않는다.** 결과:

1. **피처 오차** — `is_high_regime`·`days_since_last_pm`은 gain 1·2위(합 77%) 피처다. CH4의 요란 PM이 CH1~3 wafer의 레짐 피처까지 뒤집으면 생산의 3/4에 계통 오차가 들어간다.
2. **재학습 파급** — 한 챔버의 PM이 전 챔버 모델 재학습을 유발한다. 현 캐던스가 일간 슬라이딩(`retrain_days: 1`)이라 정기 트리거와 겹쳐 실효 피해는 작지만, 캐던스가 길어지면 드러난다.

여기서 "서빙만 챔버별로 필터하면 되지 않나"가 자연스러운 반응인데, **그게 이 ADR의 핵심 함정**이다.

## Decision

### 1. 단기 — 전역 PM 시맨틱을 **유지**한다 (B6-3-f 범위)

`chamber_id`는 **기입하되 소비하지 않는다.** 이유는 "무해해서"가 아니라 **한쪽만 바꾸면 더 나빠지기 때문**이다:

- 현 동결 모델은 **PM이 전역이던 데이터로 학습**됐다. 서빙 피처만 챔버별로 바꾸면 학습 분포와 서빙 분포가 어긋난다(train/serve skew) — 오차의 방향조차 예측하기 어렵다.
- 따라서 전환은 **학습·서빙 동시**여야 하고, 그러면 **동결 벤치 재검증**이 따라온다. B6-3-f PR에 얹을 수 있는 크기가 아니다.

기입은 지금 해둔다 — 나중에 필터를 켤 때 **소급 데이터가 있어야** 하기 때문이다. `chamber_id` 없는 엔트리가 쌓이면 전환 시점에 과거 구간을 못 쓴다.

### 2. 후속 — 챔버별 PM 필터로 전환 (별건, A 담당)

전제(전부 충족해야 착수):

- **학습·서빙 동시 전환** — `_meta_features`의 PM 조회를 wafer의 `chamber_id`로 필터. 재학습 파이프라인(`retrain`)의 피처 빌드도 같은 코드 경로라 함께 바뀐다.
- **동결 벤치 재검증** — 시간축 pooled RMSE **99.84 ± 0.5** 유지 확인. 이탈 시 전환 보류하고 원인 규명.
- **`should_retrain` 스코프 결정** — 챔버별 필터를 켜면 재학습 트리거도 챔버별로 볼지, 모델이 전 챔버 공용인 이상 전역으로 둘지를 **명시적으로 정한다**(공용 모델이면 전역 유지가 정합. 챔버별 모델 분리는 별개 결정).
- **레거시 엔트리 처리** — `chamber_id` 없는 과거 엔트리(2018-12-24 등)의 취급 규약. 전 챔버 적용 / 제외 중 택일하고 기록.

전환 시 계약 §8-B-1의 "알려진 한계" 절과 본 ADR Status를 함께 갱신한다.

## Consequences

**좋아지는 것**

- B6-3-f가 모델 재검증을 끌고 들어가지 않는다 — M3(7/30) 크리티컬 패스를 건드리지 않고 머지 가능.
- 전환 시점에 쓸 챔버 축 데이터가 **지금부터** 쌓인다.
- 한계가 계약에 문서로 남아, 시연 중 질의(§ 아래)나 이후 성능 조사에서 "왜 CH1 wafer가 post-PM인가"를 즉답할 수 있다.

**감수하는 것**

- 전환 전까지 다챔버 요란 PM은 전 챔버 피처를 흔든다. 데모 시나리오는 SC2(CH4 단독 요란)라 관측될 수 있다 — 시연 대비는 `docs/데모_서사_발표_스토리보드_v1.md` §6 Q&A에 반영.
- `chamber_id`가 "기입되지만 안 읽히는" 필드로 한동안 남는다. 읽는 쪽이 없다고 지우면 안 된다는 점을 본 ADR이 근거로 고정한다.

**하지 않기로 한 것**

- 서빙만 챔버별 필터 (train/serve skew — 위 Decision 1).
- pm_log를 챔버별 파일로 분할 (A `find_file`·캐시·경로 계약을 전부 흔들고, 전역/챔버별 선택을 파일 구조에 하드코딩하게 된다. 필터는 **읽는 쪽 로직**으로 푸는 게 되돌리기 쉽다).
