# TSR-0005: Qual 승인 방치 → 전 챔버 PHASE_0 고착 — 28시간의 주입이 무음으로 버려졌다

## Status

Resolved (운영 복구 완료 · 코드 개선 3건은 B 이관 Open)

## Context

- **발생일**: 침묵 시작 2026-08-07 05:51:28Z(`spc_violations` 마지막 적재) → 발각 2026-08-09
  리허설 왕복 1차 → 복구 2026-08-09 09:49Z(재시작) → 재검증 같은 날 10:07Z.
- **담당자**: PM (발견·진단·복구) · 팀원 B (이관 3건 — 아래)
- **관련 컴포넌트**: `provisional_mode.py`(`on_pm`·`on_qual_verdict`) ·
  `publisher.process()` ① 생성억제 · `alert_seam.py` · `quals`(HITL 승인 대기열)
- **증상**: 리허설 왕복 1차 — producer 8,247장/85,154행 정상 발행, 컨슈머 실시간 소화

- **왜 늦게 발견됐나 — 무음이 세 겹**: ⓐ `on_pm`(PHASE_0 진입)이 **무로그 전이**다
  ⓑ 억제 skip 은 **DEBUG** 로그뿐이고 `counters.suppressed` 는 어디에도 노출되지 않는다
  ⓒ 판정·tttm·예측조인 카운터는 전부 정상 INFO 를 내서 "돌고 있음"으로 보인다.
  더해서 8/7 06시~8/8 은 PR·문서 작업일이라 아무도 라이브 알람을 보지 않았다.

## Decision

### 근본 원인 — HITL 대기가 안전 억제를 무기한 붙들었다

```
PM 이벤트(pm_count↑) → on_pm → PHASE_0 (새 정상 미확립 — 알람 억제, 설계 의도)
  → Qual 5장 발행 → proposed_verdict 생성
  → approval_status=PENDING 방치  ← ★ 여기서 멈춤 (quals 208행 중 confirmed 0)
  → on_qual_verdict 는 confirmed 만 처리(헌법 1-1 HITL 하류) → PHASE_0 탈출 경로 없음
  → publisher ① 생성억제: 적재·발행 둘 다 skip (DEBUG · 카운터 무노출)
```

루프 producer 는 8/8 10:07Z 까지 바퀴마다 PM→Qual 라운드를 다시 만들며(마지막 라운드 #48·#49)
**약 28시간을 억제 상태로** 돌았다. **억제 자체는 옳다** — 오염 가능 구간에서 알람을 내지 않는
것은 G3 와 같은 철학이다. 문제는 ⓐ 그 대기가 어디에도 보이지 않았고 ⓑ 대기의 **나이**에
상한·경보가 없다는 것이다.

### 진단 체인 — 용의자 6개 기각 (오진 1회 포함)

| # | 용의자 | 판별 증거 | 결과 |
|---|---|---|---|
| 1 | 컨슈머 정지·적체 | 판정 로그 실시간 진행 + producer 종료 26초 뒤 idle tail flush | 기각 |
| 2 | 호스트 고아 이중 컨슈머 (8/5 전례) | `spc_consumer` 프로세스 0개 | 기각 |
| 3 | `publish_enabled` off | true 확인. 스위치는 **발행만** skip — 적재 0 을 설명 못 함 | 기각 |
| 4 | 부팅 phase 복구 오류 | provisional-활성 0행 → 부팅 시 전 챔버 NORMAL | 기각 — 단 ★오진 |
| 5 | `is_qual` 승계 skip | 예측 조인 **miss 100%** → is_qual=False. 동시에 collector 생존 증명 | 기각 |
| 6 | 컨테이너 코드 표류 | 리포 루트가 `/app` 바인드마운트 = 현행 코드 | 기각 |

★ **오진 기록**: 4번을 기각하며 "phase 가설 전체 기각"을 선언했다 — phase 로그 grep 0건을
"전이 없었음"으로 읽은 것. 실제 `on_pm` 은 **로그를 안 남기는 전이**라 grep 은 원리적으로
0건이다. 부팅 이후 **런타임 진입**을 배제할 수 없었다(7장 신규: "로그 0건 ≠ 사건 없음").

**결정타 4개**: `tttm_comparisons` 8,247 정확(절단면을 collector 내부로 고정) ·
quals 최근 행 전부 PENDING·confirmed 공백 · `control_limits` 에 provisional 행 0
(loud 판정 이력 없음) · 마지막 적재 8/7 05:51:28Z(침묵 시점 고정).

### 채택 해결(운영) — 재시작, 그리고 A-2 절차의 실측 근거 확보

재시작 복구(`derive_restore_state`)는 **provisional-활성 행에서만** phase 를 파생하므로
재시작 = 전 챔버 NORMAL 복귀. 재주입 8,247장 → **알람 5,969(DISTINCT alert_id) ·
그룹화 100.0% · 신규 사건 4건.** 런북 A-2 의 *"reset 후 b-spc 재시작 필수"* 가 정확히 이
고착을 끊는다 — **"매 회차 필수"의 이유가 실측으로 확인됐다.**

### 이관 3건 (B 소유 — 코드 개선)

1. **억제 누적을 N건마다 INFO** 로 노출 — 예측 조인 카운터(`예측 조인 N건: hit/miss`)와 동형.
2. **미확정 Qual 나이 경고** — phase 는 인메모리라 경과의 원천이 없지만, `quals.created_at` 은
   DB 에 있다. 가장 오래된 PENDING qual 의 나이로 계산한다(7장 *"경과는 상태의 출처(DB)에서"*
   — #137 패턴 그대로).
3. **Qual PENDING 대기열 가시화** — 승인 대기가 화면 어디서 보이는지 확인부터.

### 검토했으나 채택하지 않은 안

| 안 | 기각 사유 |
|---|---|
| PHASE_0 타임아웃 자동 해제 | 억제는 안전장치다 — 시간으로 풀면 새 레짐 미확립 상태에서 알람이 재개돼 오탐이 쏟아진다. 1-1·G3 철학 위반 |
| Qual 자동 승인 | 헌법 1-1(HITL) 정면 위반 |
| "리허설 전 A-2 재시작"에만 의존 | 리허설 밖 상시 개발 루프에서 재발한다(이번이 그 사례). 가시화가 정답 |

## Consequences

**검증**: 위 재검증 수치 + 재시작 boot 로그 `control_limits 로드 완료: 그룹 180개`.

**발표 수치 영향 없음** — 알람 기반 실측(A10 전환율·D-5 판별축 등)은 전부 8/5~8/7 05시대
데이터로, 무음 구간(8/7 05:51 이후)과 겹치지 않는다.

**남은 리스크** — 이관 3건 반영 전까지 같은 고착은 재발 가능하다(발생 조건: PM 주입 후 Qual
미승인 방치). 그 전까지는 **리허설·데모 전 A-2 재시작이 유일한 안전판**이다.

**재발 방지** — 헌법 7장에 본 PR 로 추가: "조용한 상태 게이트를 카운터만 두고 노출 없이 운용
금지" + "로그 0건을 사건 없음으로 읽지 말 것"(빈 결과 우산 조항 하위).

  일곱 번째 사례라 이제 **증상이 아니라 계보**다: 실패를 예외로 알려주지 않는 경로는 산출물
  유무로만 판정한다.
